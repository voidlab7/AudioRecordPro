# 设计规范：优化默认窗口尺寸适配 Sidebar 布局

> 角色: 绘·设计师 | Task: task-0504-ui-window-size
> 日期: 2026-05-05 | 状态: Review Complete

---

## 1. 尺寸方案评估

### 1.1 屏幕适配分析

| 设备 | 逻辑分辨率 | 80% 可用区 | 适合窗口尺寸 |
|------|-----------|-----------|-------------|
| MacBook Air 13" | 1440×900 | 1152×720 | ≤ 1024×640 |
| MacBook Pro 14" | 1512×982 | 1210×786 | ≤ 1100×700 |
| MacBook Pro 16" | 1728×1117 | 1382×894 | ≤ 1200×800 |
| 外接 27" 4K | 2560×1440 | 2048×1152 | 任意 |

### 1.2 推荐方案：**960×600**

```
┌─ 960px ──────────────────────────────────────────────────┐
│                                                    600px  │
│  Sidebar (260px)  │  Content (700px)                     │
│                   │                                       │
└───────────────────┴───────────────────────────────────────┘
```

**理由**：
- 13 寸 MacBook（1440×900）上占 67%×67%，居中后四周留白舒适
- 相比 800×500 增加 20% 面积，显著改善空间
- 不选 1024×640：在 13 寸上占 71%×71%，偏满
- 不选 800×500：当前方案，太紧凑

### 1.3 最小尺寸：**800×500（保持不变）**

- 低于 800px 时 Sidebar + Content 无法同时有效显示
- 保持向后兼容，已有用户不受影响

---

## 2. Sidebar 宽度调整

### 2.1 推荐：**260px**（从 240px 增加 20px）

| 宽度 | 进程名显示 | 按钮/面板 | 总体感受 |
|------|-----------|----------|---------|
| 240px（当前） | 长名截断（如 "Google Chrome He..."） | 略紧 | 功能可用但紧凑 |
| 260px（推荐） | 多数不截断 | 舒适 | 平衡 |
| 280px | 全部不截断 | 宽裕 | 内容区被挤（960-280=680） |

**结论**：260px 在 960px 窗口下，内容区仍有 700px，是最佳平衡点。

---

## 3. 内容区高度比例优化

### 3.1 当前比例（500px 窗口高度）

| 区域 | 高度 | 百分比 |
|------|------|--------|
| WaveformView | 42% = 210px | 42% |
| TracksView | 弹性 ≈ 84px | 17% |
| ControlPanel | 固定 150px | 30% |
| StatusBar | 固定 28px | 5.6% |
| 间距等 | ~28px | 5.4% |

### 3.2 推荐比例（600px 窗口高度）

| 区域 | 高度 | 百分比 | 变化 |
|------|------|--------|------|
| WaveformView | 38% = 228px | 38% | ↓4% 但绝对值↑ |
| TracksView | 弹性 ≈ 144px | 24% | ↑↑ 显著改善 |
| ControlPanel | 固定 120px | 20% | ↓30px（配合另一任务） |
| StatusBar | 固定 28px | 4.7% | 不变 |
| 间距等 | ~28px | 4.7% | 不变 |

### 3.3 关键调整

- **WaveformView**: 从 `multiplier: 0.42` 改为 `multiplier: 0.38`
  - 绝对值从 210px → 228px，波形显示更好
  - 最小高度保持 200px
- **ControlPanel**: 从 150px → 120px（配合 control-panel-height 任务）
  - 如该任务未实施，可暂保持 150px，TracksView 仍获得 94px（比当前 84px 好）
- **TracksView**: 弹性空间从 84px → 144px（+71%）
  - 可显示 2-3 个轨道行 + 播放面板

## 4. 响应式行为建议

### 4.1 窗口缩放规则

| 窗口宽度 | 行为 |
|---------|------|
| ≥ 960px | 正常布局，Sidebar 260px |
| 800-959px | Sidebar 缩到 240px（最小可用宽度） |
| < 800px | 不允许（minSize 限制） |

### 4.2 与 Sidebar 折叠联动（依赖 sidebar-collapse 任务）

- 窗口缩到 800px 时，提示用户可折叠 Sidebar
- 不做自动折叠（用户应自主控制）
