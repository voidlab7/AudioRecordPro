# REQ-2.0-02 启动默认录制准备态 UI 重构

## 版本：V2.0 | 优先级：P0 | 状态：⬜ 待开发

> 来源：2026-05-19 用户反馈 + `docs/AudioRecordApp知识库.md` UI 第一性原理结论  
> 当前问题：App 刚打开后的实际界面仍像“空编辑器 / 空时间线”，不是“准备录音的录音机”。

---

## 1. 一句话需求

App 启动后必须默认进入 **RecordingIdle（录制准备态）**：突出“当前录什么、能不能录、按哪里开始录”，隐藏编辑器语义和不可用操作。

---

## 2. 问题定义

当前刚打开 App 时，界面存在以下问题：

| 问题 | 当前表现 | 用户感受 |
|---|---|---|
| 状态错误 | 底部显示“录制中”，但计时器为 `00:00.00` | 不知道是否已经在录 |
| 中央区域像空时间线 | 显示时间刻度和空波形框 | 像编辑器，不像录音机 |
| 播放 / 停止按钮过强 | 初始态显示播放、录制、停止三个按钮 | 不知道主操作是哪个 |
| 导出按钮常驻 | 无文件时仍有导出入口 | 暗示已有可导出内容，语义错误 |
| 麦克风层级不清 | “同时录入麦克风”与“全部系统声音”视觉同级 | 用户可能误解为两个主目标 |
| 首屏缺少准备说明 | 中间只显示空波形 | 没有明确告诉用户当前会录什么 |

---

## 3. 产品原则

1. **刚打开是录音机，不是编辑器。**
2. **录制态只服务录制决策：录什么、有没有声音、能否开始。**
3. **编辑态必须由用户明确点击“编辑”进入，不自动露出编辑工具。**
4. **录完后先进入“回看 / 处理态”，不是直接进入完整编辑器。**
5. **无文件时不展示导出、播放、编辑等不可用动作。**

---

## 4. 目标用户故事

### US-01：首次打开

> 作为第一次打开 App 的用户，我想立刻知道当前默认会录制“全部系统声音”，并看到一个明确的“开始录制”按钮，以便无需学习就能开始录音。

### US-02：准备录制

> 作为准备录音的用户，我想确认系统声音 / 应用声音 / 麦克风的选择状态，以便避免录错来源。

### US-03：无历史文件

> 作为没有任何录音文件的用户，我不想看到导出、播放、编辑等不可用操作，以免误以为 App 状态异常。

### US-04：录完回看

> 作为刚完成录制的用户，我想先播放检查这段录音，然后再决定编辑、导出或转文字，而不是被自动带进复杂编辑器。

## 5. 目标状态设计

### 5.1 App 启动默认状态：RecordingIdle

```text
┌──────────────────────────────────────────────────────────────┐
│ AudioRecord                         准备录制 · 全部系统声音   │
├───────────────┬──────────────────────────────┬───────────────┤
│ 录制来源       │                              │ 电平监控        │
│               │      准备录制系统声音          │ L ▓▓░░         │
│ 主目标         │                              │ R ▓▓░░         │
│ ✓ 全部系统声音 │   当前目标：全部系统声音        │               │
│               │   麦克风：未开启               │               │
│ 附加输入       │   格式：48kHz · M4A/WAV        │               │
│ □ 同时录入麦克风│                              │               │
│               │   点击下方红色按钮开始录制      │               │
│ 只录某个 App   │                              │               │
│ Comet         │                              │               │
│ WeChat        │                              │               │
│ Chrome        │                              │               │
├───────────────┴──────────────────────────────┴───────────────┤
│ 00:00.00                              [   ● 开始录制   ]      │
├──────────────────────────────────────────────────────────────┤
│ 准备就绪 · 已选择：全部系统声音 · 48kHz                       │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 左侧录制来源层级

左侧不再把所有选择项做成同级卡片，必须区分：

```text
录制来源

主目标
[✓ 全部系统声音]

附加输入
[ ] 同时录入麦克风

只录某个 App
[刷新]
Comet
WeChat
Google Chrome
...
```

规则：

- `全部系统声音` 是默认主目标。
- `同时录入麦克风` 是附加输入，不是主目标。
- 应用列表是“替代主目标”或“只录某个 App”的选择区。
- 录制中禁用所有来源切换。

### 5.3 中央空状态

启动时中央区域不显示时间线刻度，不显示编辑器边框感。

必须显示：

- 主标题：`准备录制系统声音`
- 当前目标：`全部系统声音`
- 麦克风状态：`未开启 / 已开启`
- 格式信息：`48kHz · M4A/WAV`
- 引导文案：`点击下方红色按钮开始录制`

允许保留极轻量的静音基线 / 电平预览，但不能出现编辑时间尺。

### 5.4 底部控制区

初始态只突出录制按钮：

| 控件 | 初始态行为 |
|---|---|
| 计时器 | `00:00.00` |
| 录制按钮 | 主按钮，文案 `开始录制`，红色高亮 |
| 播放按钮 | 隐藏或 disabled |
| 停止按钮 | 隐藏或 disabled |
| 状态栏 | `准备就绪 · 已选择：全部系统声音 · 48kHz` |

### 5.5 顶部标题栏

| 元素 | 初始态行为 |
|---|---|
| App 名称 | 显示 `AudioRecord` |
| 当前目标 | 显示 `准备录制 · 全部系统声音` |
| 导出按钮 | 隐藏或 disabled 到低权重 |
| 编辑工具 | 不显示 |

## 6. 状态机要求

新增或明确以下 UI 工作区状态：

```swift
enum AppWorkspaceMode {
    case recordingIdle       // 刚打开 / 准备录制
    case recordingPreparing  // 权限、设备、文件初始化中
    case recordingActive     // 正在录制
    case recordingStopping   // 停止并保存中
    case review(file: RecordedFileInfo) // 录完回看 / 处理
    case editing(file: RecordedFileInfo) // 完整编辑器
    case error(message: String)
}
```

### 6.1 状态显示规则

| 状态 | 中央区域 | 底部 | 顶部导出 | 编辑工具 |
|---|---|---|---|---|
| `recordingIdle` | 准备录制空状态 | 只突出 REC | 隐藏 / disabled | 隐藏 |
| `recordingPreparing` | 准备中 / 权限中 | REC disabled | 隐藏 | 隐藏 |
| `recordingActive` | 实时波形 + 电平 | 停止录制为主 | 隐藏 | 隐藏 |
| `recordingStopping` | 保存中 | 控件 disabled | 隐藏 | 隐藏 |
| `review(file)` | 静态波形 + 播放 | 播放 / 编辑 / 导出 / 转文字 | 可用 | 不直接显示工具栏 |
| `editing(file)` | 编辑器时间线 | 预览控制 | 保存 / 另存为 | 显示 |
| `error` | 错误说明 + 重试 | 重试 / 返回准备态 | 隐藏 | 隐藏 |

---

## 7. 功能范围

### In Scope

- 修复 App 刚打开时错误显示“录制中”的问题。
- 初始中央区域改为“准备录制”空状态。
- 初始态隐藏时间线刻度和编辑器语义。
- 初始态弱化 / 隐藏播放、停止、导出等不可用动作。
- 左侧录制来源重构为“主目标 / 附加输入 / 只录某个 App”三层。
- 录制完成后进入 `review(file)`，显示播放、编辑、导出、转文字入口。
- 用户点击“编辑”后才进入完整 `EditorViewController`。

### Not in Scope

- 不实现新的音频编辑算法。
- 不实现多轨混音。
- 不接入 Mute / Solo 的真实音频处理。
- 不实现转文字功能，仅预留入口或占位。
- 不改底层 CoreAudio / AVFoundation 录制实现。
- 不重做完整编辑器时间线 UI；本需求只修正启动态与录制/回看边界。

## 9. 验收标准

### 9.1 启动状态

- [ ] App 启动后状态栏显示 `准备就绪`，不得显示 `录制中`。
- [ ] 计时器显示 `00:00.00`。
- [ ] 中央区域显示“准备录制系统声音”的空状态说明。
- [ ] 中央区域不显示时间线刻度 `0:00 / 0:01 / 0:02`。
- [ ] 初始态不显示 `EditToolbarView`。
- [ ] 初始态不显示 `TrackPanelView` / Mute / Solo。
- [ ] 初始态导出按钮隐藏或 disabled。
- [ ] 初始态播放按钮和停止按钮隐藏或 disabled，录制按钮是唯一主 CTA。

### 9.2 左侧来源选择

- [ ] 左侧明确区分 `主目标`、`附加输入`、`只录某个 App`。
- [ ] 默认主目标为 `全部系统声音`。
- [ ] `同时录入麦克风` 显示为附加输入，不与系统声音视觉同级。
- [ ] 选择某个 App 后，标题栏和状态栏同步显示目标。

### 9.3 录制流程

- [ ] 点击 `开始录制` 后进入 `recordingPreparing` / `recordingActive`。
- [ ] 录制中显示实时波形、计时器、电平。
- [ ] 录制中禁止切换来源、进入编辑、导出。
- [ ] 停止录制后进入 `review(file)`，不是直接显示完整编辑工具栏。

### 9.4 回看 / 处理态

- [ ] 录制完成后显示已保存文件名和静态波形。
- [ ] 回看态提供 `播放`、`编辑`、`导出`、`转文字` 四类入口（转文字可 disabled / coming soon）。
- [ ] 点击 `编辑` 才进入 `EditorViewController`。
- [ ] 返回编辑器后可回到回看或录制准备态。

### 9.5 回归

- [ ] 系统音频录制仍可正常开始和停止。
- [ ] 指定 App 录制仍可选择并开始。
- [ ] 麦克风附加输入开关不受影响。
- [ ] 历史录音文件列表不受影响。
- [ ] 编译通过。

## 11. 下游建议

### 给绘（设计）

需要产出一张启动态视觉稿或结构说明：

- RecordingIdle
- RecordingActive
- Review(file)

重点检查：层级、空状态、CTA、不可用按钮的处理。

### 给矩（架构）

需要审查 `AppWorkspaceMode` 是否应该替代当前 `MainWindowView.ViewMode`，避免状态继续分散。

### 给铸（开发）

优先修复状态和布局，不要顺手重写编辑器。最小改动目标是：首屏像录音机，录完先回看，点击编辑才进编辑器。

### 给鉴（QA）

重点测启动态、录制态、录完回看态、编辑入口四条路径，不只测录制成功。
