## 一、设计背景与问题定义

### 1.1 当前问题

启动 App 后的首屏 UI 存在信息架构错误：

1. **中间区域像"空编辑器"**：有时间线刻度（`0:00 / 0:01 / 0:02 / 0:05`），但用户还没有录制或加载任何音频
2. **状态文字矛盾**：左下角显示 `● 录制中`，但计时器是 `00:00.00`，暗示未开始录制
3. **编辑能力过早暴露**：播放/停止按钮、导出按钮在首屏就常驻显示，暗示"这是一个编辑器"
4. **麦克风与大目标同级**：`全部系统声音` 和 `同时录入麦克风` 都是大卡片，用户误以为两者是同级主目标

### 1.2 第一性原理分析

用户打开 App 的第一意图是：

> **"我要把 Mac 上的声音录下来，而且要录对。"**

因此首屏必须回答的问题只有：

1. 我在录什么？（音源）
2. 有没有权限？（麦克风 / 系统音频）
3. 有没有声音进来？（电平）
4. 怎么开始录？（REC 按钮）
5. 录完去哪找？（文件列表入口）

**首屏不应该回答的问题**：

- 怎么裁剪音频？
- 怎么标准化？
- 怎么加淡入淡出？
- 多轨混音怎么弄？

这些是第**二意图**（录完后的处理），不应该在首屏占用认知资源。

## 二、设计目标与原则

### 2.1 设计目标

1. **首屏 = 专业录音机**：打开 App 立刻知道"这是用来录音的"
2. **录制准备态极简**：只展示录音必需信息，不暴露编辑能力
3. **状态清晰**：`准备就绪` / `录制中` / `已保存` 三种状态有明确视觉区分
4. **编辑能力按需出现**：只有用户明确进入"编辑态"才展示编辑工具
5. **信息层级清楚**：主目标（系统声音 / 麦克风）与附加输入（第二音源）有明确层级

### 2.2 设计原则

引用 `设计_绘/SOUL.md` 中的原则：

1. **每个屏幕有层次** — 用户先看什么？第二看什么？
2. **默认做减法** — 如果一个 UI 元素没有赢得它的像素，砍掉它
3. **空状态是功能** — 没有录音时的空状态应该帮助用户理解"接下来会发生什么"
4. **具体胜过氛围** — "干净、现代的 UI"不是设计决策，具体说明每个元素的目的

## 三、信息架构重设计

### 3.1 三种工作区模型

取代当前的"单一界面混合录制+编辑"，改为三种明确的工作区：

```
工作区 1：RecordingIdle（录制准备态）
  - 默认打开 App 进入
  - 只展示录制相关功能
  - 不展示编辑工具

工作区 2：RecordingActive（录制进行态）
  - 点击 REC 后进入
  - 展示实时波形、电平、计时器
  - 只提供"停止"操作，不提供编辑操作

工作区 3：PlaybackReview（回看态）
  - 录制完成自动进入
  - 展示静态波形、播放控制
  - 提供 [编辑] [导出] [转文字] 三个主操作
  - 不展示完整编辑时间线
```

**关键决策**：录制完成后**不自动进入完整编辑器**，而是进入"回看/处理态"。用户明确点击 `[编辑]` 才进入编辑工作区。

### 3.2 首屏（RecordingIdle）信息架构

```
┌──────────────────────────────────────────────────────────────┐
│ 导航栏                                                     │
│ [Logo] AudioRecord               [设置] [最小化] [关闭]     │
├───────────────┬──────────────────────────────┬─────────────┤
│ 左侧面板        │ 中间主区域                      │ 右侧面板      │
│                │                                  │              │
│ 录制来源        │  准备录制系统声音                │ 电平监控      │
│                │                                  │              │
│ ✓ 全部系统声音  │   点击下方红色按钮开始录制        │ L ▓▓░░       │
│ + 麦克风可选    │                                  │ R ▓▓░░       │
│                │   当前设置：48kHz · WAV/M4A      │              │
│ 只录某个 App   │                                  │              │
│ Comet          │                                  │              │
│ WeChat         │                                  │              │
│ Chrome         │                                  │              │
├───────────────┴──────────────────────────────┴─────────────┤
│ 状态栏                                                      │
│ 00:00.00                         [     ● REC     ]           │
├──────────────────────────────────────────────────────────────┤
│ 底部状态栏                                                   │
│ ● 准备就绪 | 48kHz | 全部系统声音                          │
└──────────────────────────────────────────────────────────────┘
```

#### 信息层级

| 层级 | 元素 | 目的 |
|------|------|------|
| 1（最先被看到） | REC 按钮 | 主操作 |
| 2 | 中间"准备录制"提示 | 告知当前状态 |
| 3 | 左侧录制来源 | 确认/修改录制目标 |
| 4 | 右侧电平监控 | 确认有声音输入 |
| 5（最次要） | 底部状态栏 | 详细技术信息 |

### 3.3 状态定义与切换

#### 状态 1：准备就绪（RecordingIdle）

- **触发**：App 启动 / 录制停止后
- **左侧**：显示录制来源选择
- **中间**：显示"准备录制"空状态 + 当前设置
- **右侧**：显示电平监控（实时刷新，但未录制）
- **底部**：REC 按钮可用，播放/停止禁用
- **状态栏**：`● 准备就绪 | 48kHz | 全部系统声音`

#### 状态 2：录制中（RecordingActive）

- **触发**：用户点击 REC
- **左侧**：录制来源变为不可编辑（防止录制中切换）
- **中间**：显示实时波形 + 计时器
- **右侧**：电平监控高亮（可能加录制指示器）
- **底部**：REC 按钮变为 STOP 按钮（或保留 REC，变为停止样式）
- **状态栏**：`● 录制中 | 00:12 | 48kHz`

#### 状态 3：回看态（PlaybackReview）

- **触发**：录制停止
- **左侧**：显示当前文件信息 + 文件列表入口
- **中间**：显示静态波形 + 播放进度条
- **右侧**：电平监控变为播放电平（可选）
- **底部**：播放/暂停/停止按钮可用；新增 [编辑] [导出] [转文字] 按钮
- **状态栏**：`已保存：系统音频_20260519-1530.wav`

## 四、具体 UI 组件设计

### 4.1 左侧面板：录制来源选择

#### 当前问题

- `全部系统声音` 和 `同时录入麦克风` 都是大卡片，视觉上同级
- 用户误以为"同时录入麦克风"是独立主目标，实际上它是附加输入

#### 重新设计

```
录制来源
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

主目标
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
○ 全部系统声音
○ 仅麦克风
○ 仅某个 App

附加输入
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
☐ 同时录入麦克风（作为第二轨）


只录某个 App（主目标选"仅某个 App"时显示）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[刷新按钮]
• Comet
• WeChat
• Google Chrome
• ...
```

**关键变化**：

1. **主目标 vs 附加输入分离**：用分隔线和标题区分
2. **单选 vs 复选**：主目标是单选（○），附加输入是复选（☐）
3. **条件显示**："只录某个 App"列表只在主目标选"仅某个 App"时显示

### 4.2 中间主区域：录制准备空状态

#### 当前问题

- 显示时间线刻度（`0:00 / 0:01 / 0:02 / 0:05`），暗示"这里有音频"
- 实际上没有音频，这是空的编辑器

#### 重新设计

```
┌─────────────────────────────────┐
│                                 │
│        准备录制系统声音           │
│                                 │
│   当前目标：全部系统声音         │
│   不会录制：麦克风              │
│   保存格式：WAV 48kHz          │
│                                 │
│   点击下方红色按钮开始录制       │
│                                 │
│   ℹ️ 提示：首次使用需要授权    │
│     系统音频录制权限             │
│                                 │
└─────────────────────────────────┘
```

**关键变化**：

1. **不显示时间线刻度**：没有音频时不应该有时间线
2. **显示当前设置**：让用户确认"我要录的是这个吗？"
3. **显示权限提示**：如果尚未授权，显示授权引导
4. **居中排版**：空状态应该居中，引导用户注意力到 REC 按钮

#### 录制中的中间区域

```
┌─────────────────────────────────┐
│ 实时波形（从左到右绘制）         │
│  ▃▄▅▇▆▅▄▃▄▅▇▆▅▃               │
│                                 │
│ 00:12.345                      │
│                                 │
│ [停止录制]                     │
└─────────────────────────────────┘
```

**关键变化**：

1. **波形从左到右绘制**：表示"正在录制"
2. **计时器精确到毫秒**：专业用户关心这个
3. **停止按钮突出**：录制中最重要操作是"停止"

### 4.3 底部控制栏

#### 当前问题

- 播放、录制、停止三个按钮同等突出
- 录制未开始时，播放和停止不应该可用

#### 重新设计

**准备就绪状态**：

```
00:00.00                    [     ● 开始录制     ]
```

- 播放按钮：隐藏
- 停止按钮：隐藏
- REC 按钮：唯一按钮，最大尺寸，红色

**录制中状态**：

```
00:12.345                          [  ■ 停止录制  ]
```

- 播放按钮：隐藏（录制中不能播放）
- REC 按钮：变为停止按钮（黑色或灰色，非红色）

**回看态**：

```
00:12.345    [▶️ 播放] [⏸ 暂停] [⏹ 停止]    [编辑] [导出] [转文字]
```

- 播放控制：显示
- 编辑/导出/转文字：新增，作为回看态的主操作

### 4.4 顶部状态栏

#### 当前问题

- 显示 `● 录制中`，但计时器是 `00:00.00`
- 用户困惑："到底在录还是没录？"

#### 重新设计

| 状态 | 显示文字 | 颜色 |
|------|---------|------|
| 准备就绪 | `● 准备就绪 \| 48kHz \| 全部系统声音` | 灰色 |
| 录制中 | `● 录制中 \| 00:12 \| 48kHz` | 红色闪烁 |
| 已保存 | `已保存：系统音频_20260519-1530.wav` | 绿色 |

**关键变化**：

1. **状态文字准确**：不录制时显示"准备就绪"，不显示"录制中"
2. **计时器只在录制中显示**：准备就绪时显示 `00:00.00` 无意义
3. **颜色编码**：灰色（待机）、红色（录制）、绿色（完成）

## 五、交互设计

### 5.1 核心用户旅程

#### 旅程 1：首次录制

```
1. 用户打开 App
   → 显示"准备就绪"状态
   → 显示权限引导（如果未授权）

2. 用户点击 REC
   → 如果未授权，弹出授权引导
   → 授权完成后开始录制

3. 开始录制
   → 状态变为"录制中"
   → 显示实时波形和计时器

4. 用户点击停止
   → 状态变为"已保存"
   → 显示回看态
   → 提供 [编辑] [导出] [转文字] 按钮

5. 用户点击 [编辑]
   → 进入编辑工作区（另一需求）
```

#### 旅程 2：切换录制目标后录制

```
1. 用户在左侧选择"仅某个 App"
   → 显示 App 列表

2. 用户选择"Comet"
   → 中间区域更新："准备录制 Comet 的音频"

3. 用户点击 REC
   → 开始录制 Comet 的音频
```

### 5.2 边界情况处理

#### 边界情况 1：没有录音权限

```
显示权限引导界面：

┌─────────────────────────────────┐
│ ⚠️ 需要录音权限                │
│                                 │
│ 为了录制系统音频，需要授权：    │
│                                 │
│ 1. 系统音频录制权限             │
│    [前往系统设置]               │
│                                 │
│ 2. 麦克风权限（可选）           │
│    [前往系统设置]               │
│                                 │
│ 授权完成后，点击此处刷新状态    │
│   [刷新状态]                   │
└─────────────────────────────────┘
```

#### 边界情况 2：录制目标无声音

```
录制中，但右侧电平监控一直为零：

显示警告：

┌─────────────────────────────────┐
│ ⚠️ 未检测到声音输入            │
│                                 │
│ 可能原因：                      │
│ • 系统音频录制未正确配置        │
│ • 选择的 App 没有播放音频       │
│ • 麦克风被静音                 │
│                                 │
│ [查看故障排除指南]              │
└─────────────────────────────────┘
```

#### 边界情况 3：磁盘空间不足

```
点击 REC 时检查磁盘空间：

如果可用空间 < 100MB：
  显示警告："磁盘空间不足，可能无法保存录制文件"
  提供选项：[取消] [仍然录制]

如果可用空间 < 10MB：
  禁止录制，显示："磁盘空间已满，请清理后重试"
```

## 七、验收标准

### 7.1 功能验收

1. **启动默认进入录制准备态**：
   - 打开 App，中间区域显示"准备录制"空状态
   - 不显示时间线刻度
   - 不显示编辑工具栏

2. **状态显示准确**：
   - 准备就绪：`● 准备就绪`
   - 录制中：`● 录制中 | 00:XX`
   - 已保存：`已保存：xxx.wav`

3. **按钮显示正确**：
   - 准备就绪：只显示 REC 按钮
   - 录制中：只显示停止按钮
   - 回看态：显示播放控制 + [编辑] [导出] [转文字]

4. **左侧面板层级清楚**：
   - 主目标（系统声音/麦克风/某个 App）是单选
   - 附加输入（同时录入麦克风）是复选
   - 两者有明显视觉区分

### 7.2 设计验收

1. **信息层级**：REC 按钮是最突出的元素
2. **空状态有用**：不是"空白"，而是引导用户理解下一步
3. **状态明确**：用户任何时候都知道"现在处于什么状态"
4. **不做多余**：没有录制时不显示编辑相关能力

## 八、开放问题与后续决策

1. **[待定] 回看态是否显示静态波形？**
   - 选项 A：显示静态波形（帮助用户确认录制内容）
   - 选项 B：不显示波形，只显示文件信息和操作按钮
   - 建议：选项 A，但需要简化波形视图（不需要时间线刻度）

2. **[待定] 编辑工作区是模态还是切换？**
   - 选项 A：点击 [编辑] 后整个界面切换到编辑工作区
   - 选项 B：点击 [编辑] 后弹出模态编辑窗口
   - 建议：选项 A（整个界面切换，因为编辑是主要功能）

3. **[待定] 文件列表在哪里显示？**
   - 选项 A：左侧面板底部常驻显示最近录制的文件
   - 选项 B：独立"文件"标签页
   - 建议：选项 B（独立标签页，避免首屏信息过载）
