# REQ-2.0-06 多应用同时录音 + 多轨道显示 — PRD

**创建**: 2026-05-30 | **版本**: V1.0 | **状态**: 草稿
**负责人**: PM_枢 | **审批人**: CEO_锋

---

## 0. 一句话描述

支持用户在侧边栏同时勾选多个应用，每个应用独立录制为一条轨道，录制过程中主区域显示所有轨道的实时滚动波形。

---

## 1. 问题 & 假设

### 问题
- **要解决的问题**: 当前录制模式只支持"全部系统声音"混录或单个进程录制，用户无法同时选择多个应用独立录制
- **不做会怎样**: 用户无法同时录制多个应用的独立音频，只能退而求其次使用系统混录（丢失独立性），或逐个应用录制（效率极低）
- **现状**: 用户需要逐个应用录制，每次录制生成一个混录文件；或者使用系统混音录制，无法分离各应用音源

### 假设
- **核心假设**: 用户有"同时录制多个应用独立音频"的真实需求（竞品 Audio Capture Pro 已支持此功能）
- **最危险的假设**: macOS ScreenCaptureKit/ProcessTap 支持同时对多个 PID 建立独立 tap（需技术 Spike 验证）
- **验证方式**: 技术 Spike — 同时为 3 个 PID 创建独立 ProcessTap，验证 macOS 是否支持

---

## 2. 目标用户

- **具体画像**: 需要同时录制多个应用音频的 Mac 用户——播客制作人（录制浏览器+音乐播放器）、线上课程录制者（录制会议+演示文稿）、游戏录制者（录制游戏+语音聊天）
- **Jobs-to-be-Done**: "我想同时录制 Chrome 的网页声音和 QQ Music 的音乐，并且录完之后每个应用是独立的音频文件"
- **使用场景**: 多窗口办公场景——左侧浏览器、右侧音乐播放器，需要各自独立录制
- **用户规模**: 与当前单进程录制用户群相同，多轨需求是高频进阶需求

---

## 3. MVP 定义

- **最小闭环**: 侧边栏 Checkbox 多选 → 多轨道实时波形显示 → 多进程并行录制 → 生成 N 个独立音频文件
- **验证什么**: 用户是否真的使用多选功能（同时勾选 2+ 应用），以及多轨录制是否稳定
- **成功指标**: 多选使用率 > 30%（在选择了录制目标的用户中）；多轨录制成功率 > 99%
- **失败标准**: 多选使用率 < 5%（功能无人用）或多轨录制崩溃率 > 1%（不稳定）

## 6. 交互流程

### 核心路径（Happy Path）
```
用户打开侧边栏 → 勾选多个应用 Checkbox → 右侧轨道区等分显示 N 条轨道
→ 点击"录制"按钮 → 锁定勾选状态 → 多轨道同时录制 + 实时波形
→ 点击"停止" → 生成 N 个独立音频文件 → 进入编辑器
```

### 异常路径
```
录制中某应用退出 → 该轨道标记"已断开"(灰色) → 其他轨道继续 → 录制结束提示"1 个音源已断开"
磁盘空间不足 → 所有轨道同时停止 → 已录部分保留 → 提示用户
勾选 6+ 个应用 → 提示"最多同时录制 5 个音源" → 阻止勾选第 6 个
```

### 边界情况
- [x] 空状态——第一次使用，没有应用可选择（无音频进程运行）
- [x] 极端数据——应用名称含特殊字符（斜杠、冒号等，文件命名需转义）
- [x] 单应用退化为当前行为——只勾选 1 个应用时，波形铺满，行为与改造前一致
- [x] 并发操作——快速连续勾选/取消多个 Checkbox
- [x] 录制中无声音——正常录制静音数据，波形显示平线

## 7. 数据需求

| 数据 | 来源 | 格式 | 更新频率 |
|------|------|------|---------|
| 可录制音频进程列表 | `AudioProcessEnumerator.getAvailableAudioProcesses()` | `[AudioProcessInfo]` | 每次打开侧边栏时刷新 |
| 应用图标 | 进程路径 / bundleID 查找 | `NSImage` (24×24) | 首次显示时加载+缓存 |
| 各轨道实时波形 | `CoreAudioProcessTapRecorder` 回调 | PCM 样本数据 | 每帧 (~20ms) |
| 各轨道电平值 | `AudioCallbackHandler` | `Float` (0.0-1.0) | 每帧 (~20ms) |
| 录制文件路径 | `AudioToolboxFileManager` | `URL` | 录制完成时生成 |

## 9. 风险 & 缓解

| # | 风险 | 概率 | 影响 | 缓解方案 |
|---|------|------|------|---------|
| 1 | macOS 不支持同时多 PID 独立 ProcessTap | 中 | 高 | **降级方案**: 若 Spike 失败，采用系统混录 + 后处理分离（频率/特征识别拆分）或单进程轮流录制 |

| 4 | 应用退出或崩溃时的音频流中断处理 | 中 | 低 | 捕获进程退出通知；标记断连；已录数据保留 |
| 5 | 文件名含特殊字符导致写入失败 | 低 | 中 | 文件名清理：特殊字符替换为 `_` |

## 降级方案（技术 Spike 失败时启用）

如果 macOS 不支持同时多 PID 独立 ProcessTap，采用以下降级方案：

**方案 1: 系统混录 + 后处理分离**
- 录制时仍使用系统混音模式
- 录制完成后，通过频率特征识别（频谱分析）尝试分离各应用音频
- 优点：录制引擎改动最小
- 缺点：分离精度有限，音频重叠部分无法完美分离

**方案 2: 轮流快速切换录制**
- 每个应用轮流录制 500ms 片段
- 播放时按时间对齐拼接
- 优点：每个应用确实有独立音频
- 缺点：每个应用实际只有 50% 的录制时间（N 个应用时），音频不连续

**方案 3: 虚拟音频设备路由**
- 为每个应用创建独立的虚拟音频设备
- 通过 Aggregate Device 将各应用音频路由到独立设备
- 优点：真正独立的音频流
- 缺点：复杂度极高，需要系统级权限
