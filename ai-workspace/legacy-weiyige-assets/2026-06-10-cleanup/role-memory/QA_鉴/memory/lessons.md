# QA（鉴） — 经验教训

> 最后更新: 2026-05-17

## 教训列表

### L-001 交互层缺失是最致命的 BUG（2026-05-17）
- **事件**：V1.1 编辑器 4 个 Command 算法全部正确，但波形视图缺少"拖拽创建选区"这个最基础的交互，导致裁剪功能完全不可用
- **教训**：算法实现和 UI 交互是两个独立维度。代码审查不能只看"方法存在"，必须追踪完整的用户操作路径：`用户动作 → 事件捕获 → 状态变更 → UI 反馈 → 功能触发`。如果中间任何一环缺失，功能就等于不存在
- **检查清单**：以后每个功能必须验证 `mouseDown/mouseDragged/mouseUp` 的完整链路，不能只看 delegate 方法是否存在

### L-002 IndustrialIconButtonView 64×64 硬编码是定时炸弹（2026-05-17）
- **事件**：`IndustrialIconButtonView` 硬编码 `width=64, height=64`，放在 44px 导航栏和 44px 操作栏中严重溢出
- **教训**：复用组件时必须检查其尺寸约束是否适配目标容器。硬编码尺寸的组件不能随意复用到不同高度的容器中
- **规则**：对任何新 UI 组件，检查其 `widthAnchor/heightAnchor` 约束是否有硬编码值，如有则确认目标容器能容纳

### L-003 setAllToolsEnabled(true) 是危险操作（2026-05-17）
- **事件**：`loadAudio` 完成后调 `setAllToolsEnabled(true)` 启用所有按钮，包括裁剪——但裁剪需要选区才能工作。按钮亮着但点了没反应
- **教训**：批量启用控件后必须紧接着调用一次精确的状态同步（如 `didChangeSelection(nil)`），确保每个按钮的启用条件被正确评估
- **规则**：`setAllEnabled(true)` 后面必须跟 `syncIndividualStates()`

### L-004 静默失败是最差的用户体验（2026-05-17）
- **事件**：多个操作失败时只打 log 不给用户反馈（NormalizeCommand 信号太弱返回 nil、performTrim 无选区直接 return）
- **教训**：每个用户可见的按钮/操作，失败时必须有对应的用户可见反馈（NSAlert/状态栏/toast）。`return` 不等于处理了错误
- **规则**：`guard ... else { return }` 的 else 分支必须包含用户反馈

### L-005 前一轮 QA 误判"通过"（2026-05-17）
- **事件**：Week 1 QA 报告给了 92/100 分并标记"通过"，但实际上最核心的功能（创建选区→裁剪）完全不可用
- **教训**：代码审查级 QA 容易被"方法存在=功能实现"误导。必须追踪完整的用户操作路径，不能只看代码结构
- **规则**：每个 REQ 验收必须写出完整的用户操作步骤（Given/When/Then）并逐步追踪代码执行路径
