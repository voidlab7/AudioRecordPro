# PM（枢） — 经验教训

> 最后更新: 2026-05-25

## 教训列表

### 1. V2.0 插队打乱节奏
- **场景**: V1.0 接近完成时，UI 信息架构问题暴露，V2.0 需求插队
- **教训**: 插队需求虽然正确，但打断了 V1.0 → V1.1 的线性推进。应该先快速闭环 V1.0 再处理
- **行动**: 未来插队需求需评估对当前里程碑的影响，优先闭环再插队

### 2. QA Bug 未及时闭环
- **场景**: 5月14日 QA 报告发现 3 个中优先级 Bug，至 5月25日仍未确认修复
- **教训**: Bug 修复应有明确的 SLA（中优先级 < 3 天），否则会拖慢整体进度
- **行动**: 建立 Bug 修复跟踪机制，中优先级 Bug 3 天内必须闭环

### 3. 产品状态文档缺失
- **场景**: PM 知识库为空，ai-workspace/product-state.md 不存在
- **教训**: 没有产品状态文档，每次讨论都需要从代码考古，浪费大量 Token
- **行动**: 建立并持续维护 product-state.md，每次功能变更后更新

### 4. 代码与文档不一致积累
- **场景**: 混录比例（文档 100%+100% vs 代码 0.6+0.4）、格式设置未打通等
- **教训**: 代码实现偏离文档规格时未及时同步，导致产品行为与预期不符
- **行动**: 每次代码变更后检查是否需要同步更新 knowledge/ 文档
