# PM（枢） — 领域知识

> 最后更新: 2026-05-25

## 产品定位

- **产品名**: AudioRecord Mac
- **一句话定位**: Mac 上录制任何声音，一键转文字
- **产品形态**: macOS 原生桌面应用（AppKit），纯本地运行，无后端依赖
- **核心价值链**: 获取层（系统音频录制）→ 转换层（转文字）→ 处理层（用户自行 AI 处理）
- **我们做**: 获取层 + 转换层；不做处理层（成本太高）
- **产品原则**: 录制优先 + 轻编辑 + 后续 AI 增强，不演化为复杂 DAW

## 竞品差异化

- **vs Audio Capture Pro**（¥128/年）: 我们多了轻编辑 + 格式转换 + 转文字
- **vs Otter.ai**（$8.33/月）: 我们多了录制能力，他们只做转文字
- **vs Krisp**（$8/月）: 我们多了录制+编辑，他们只做降噪
- **核心壁垒**: 录制 + 轻编辑 + 本地转写的一站式闭环

## 关键设计决策

| 日期 | 决策 | 理由 |
|------|------|------|
| 2026-05 | 产品方向确定为"录制+轻编辑+转文字" | 竞品分析 + 顾问隐多元思维评估 |
| 2026-05 | V1.x 定价 $4.99/月 | 低于竞品组合价，性价比策略 |
| 2026-05 | V2.0 UI 修正插队 | 用户反馈信息架构混乱，录制态/编辑态混杂 |
| 2026-05 | 两态工作区模型 | 录制工作区 + 编辑工作区明确分离 |
| 2026-05 | 编辑器参考剪映时间线 | 轨道头+波形片段同一行，非独立卡片 |
| 2026-05-25 | 编辑器必须有可见缩放控件 | 用户反馈不知道怎么放大/缩小波形，不能仅依赖隐藏手势 |
| 2026-05-25 | 缩放控件放底部工具栏右侧 | 编辑工具在底部，缩放是编辑辅助操作，放一起更自然 |
| 2026-05-27 | 录制完成后直接进入编辑器 | 去除 playbackReview 中间态，零决策成本，路径最短，符合"录制+轻编辑"定位 |
| 2026-05-27 | 删除 quickActionsBar 浮层 | 弹窗视觉突兀、8秒消失可能错过、不符合竞品惯例，直接进编辑器更优 |
| 2026-05-27 | 状态机简化为 3 态 | idle → recording → editing，去掉 playbackReview 中间态 |
| 2026-05-31 | 进程选择不使用 Checkbox | 选中状态用边框高亮（primaryContainer + 2px 加粗）表示，减少视觉杂乱 |
| 2026-05-31 | 多应用选择交互改为 Cmd+点击 | 无 Checkbox 后，用 Cmd+点击实现多选，与 macOS 交互规范一致 |

## NOT in Scope（明确不做）

| 功能 | 为什么不做 |
|------|----------|
| 复杂多轨混音 | 不是 DAW，保持轻量 |
| 音频特效（回声/混响） | 超出轻编辑范围 |
| 变声/换音色 | 非核心场景 |
| 精确波形编辑 | 专业 DAW 的事 |
| 实时效果预览 | 成本高，V1.x 不做 |
| AI 处理层（总结/翻译） | 用户自行处理，成本太高 |

## 技术约束

- macOS 原生（AppKit），最低支持 macOS 14.4+
- 纯本地应用，无后端服务器
- 录制引擎基于 CoreAudio Process Tap（macOS 14.4+），不依赖 ScreenCaptureKit
- V2.x 模型分发: Hugging Face → Cloudflare R2（出站免费）
- App Store 分发为主，需准备非 MAS 备案
