# Loop 开发循环协议（录音工程 · 自动加载）

> 本规则每次会话自动生效。完整宪法：`docs/LOOP.md`。总纲：`AIAgent/research/LoopEngineering/LOOP-ENGINEERING-指导方针.md`。

## 当老板说「跑 loop」/「继续跑 loop」时，按以下方式运转：

1. **读状态**：读 `TODOS.md`，取优先级最高的 `todo` 单开工
2. **交付**：实现 → 自验（`build-app.sh` + E2E + afinfo/日志硬验证）→ 不满足就修，≤3 轮
3. **写状态**：全绿后置 `ready-for-review`，附四样证据（构建摘要/硬验证输出/回归结论/标准勾选清单）
4. **继续**：置完状态后**必须重读 `TODOS.md`** 再取下一张 `todo`——需求台会话随时会入池新单/打回/改优先级，会话内缓存的池子已过期（2026-10-12 老板增）。不停下来等老板
5. **停止条件**：池中无 `todo`，或某单 `blocked`（轮次耗尽/方向分歧）→ 停下汇报

## 🚗 自动驾驶模式（「自动驾驶」/「夜跑」触发，或 automation 定时触发）

在「跑 loop」基础上追加：

1. **签收异步化**：`ready-for-review` 不是终点，置完状态+证据后**重读 `TODOS.md`**（可能有新单入池）再**立即**继续下一张 `todo`，绝不等待老板签收。老板滞后批量签收（次日晨审），打回的单带修正说明回 `todo`。
2. **上限**：一晚上最多 8 张单 / 5 小时（先到者停）；到了即收工写报告。
3. **反阻塞**：单内遇歧义 → 写推理继续，不停在歧义上等人；3 种方案都不行 → 带 TODO 置 `blocked`，继续下一张。
4. **收工报告**：列出每张单的最终状态、`ready-for-review` 清单（含证据路径）、`blocked` 清单，供老板次日晨审。

## 四条铁律（违反即产出无效）

1. **单子带标准**：无验收标准的单不开工，先起草标准请老板签
2. **做完必自验**：禁止「应该没问题」式口头完成，必须硬验证 + 证据落盘
3. **问题必回池**：自验/运行中发现新问题 → 写成新单回 `TODOS.md`，不丢在对话里，不顺手夹带
4. **单间必重读池**（2026-10-12 老板增）：每完成一张单，先重读 `TODOS.md` 拿最新池再取下一张——需求台随时入池新单/打回/调优先级，凭会话内缓存续跑视为违反状态唯一真相原则

## Git 纪律（2026-10-11 增，详见宪法 §八）

- **done/ready-for-review = 一次提交**：单号进 message（`fix(FIX-003): ...`），该单文件 + TODOS.md 状态行同一 commit
- **提交日志 = 归档日志**：`git log --grep <单号>` 即回溯入口，不另建日志文件
- **交叉文件**归改动最大的单，message 注明；push 由老板确认，本地 commit 自动执行

## 状态机

```
todo → doing → self-verify → ready-for-review → done
                      ↘ 失败≤3轮 → 修 → 回 self-verify
                      ↘ 轮次耗尽/分歧 → blocked（带证据找老板）
```

**签收即归档**（2026-10-12 增）：单子签收当天正文迁 `docs/归档/TODOS-done-YYYY-MM.md`，池里只留速览表/索引一行——控制「单间必重读池」的注入成本（详见 `docs/LOOP.md` §十二）。

## 刹车（2026-09-21 补充，防通宵空转）

- **会话预算**：一次「跑 loop」默认 2 小时，到点收束存盘，不自动开新一轮
- **同类失败止损**：同一错误模式连续 3 次无进展 → blocked
- **系统级故障**（进程杀不掉/命令反复超时/锁残留）→ 立即停，等干净环境，不深夜搏斗

`ready-for-review` 后不等待签收，直接跑下一张 `todo`（签收是老板的滞后批量动作）。

## 老板只做三件事

- **定义**：写/批准验收标准（可一次性批量定义 N 张单进池）
- **裁决**：blocked 条目、方向分歧、测试失败定责、P2 批量否决
- **签收**：看证据，不盯过程；**滞后批量**（次日晨审一次签一整晚）

## 会话接续

- 状态唯一真相 = `TODOS.md`；会话中断/单子未完成 → 状态原样留文件
- 新会话说「继续跑 loop」即无损续接，老板不重述需求
- 每张单优先用 task 子代理执行（上下文隔离），主对话只做编排与状态写回
