# AudioRecordMac 产品方案现状

> 更新时间：2026-05-03
> 角色视角：PM（枢）+ 设计（绘）
> 结论：产品核心闭环已经成型，但还没到可公开发布的“完整产品”状态。当前最强的是技术能力和视觉风格，最弱的是发布级体验闭环、格式/播放/快捷操作和文档一致性。

## 1. 产品定位

AudioRecordMac 是一个 macOS 原生系统音频录制工具，核心差异化是：

- 录制全部系统声音。
- 录制指定 App / 进程声音。
- 可把麦克风混入当前录制目标。
- 用工业风 AppKit UI 降低专业录音工具的使用门槛。

更准确的一句话定位：

> 一键录制 Mac 上任意 App 的声音，并可按需混入麦克风。

当前不适合定位成完整 DAW、剪辑软件或 Audio Hijack 全功能替代。更适合先做“更简单、更轻量、更现代的 App 音频录制器”。

## 2. 当前产品闭环

```text
打开 App
  → 默认选择“全部系统声音”
  → 可切换到指定 App 声音
  → 可选择是否同时录入麦克风
  → 点击录制
  → 查看实时波形/电平/轨道状态
  → 停止录制
  → 文件出现在 Saved Files
  → Finder 打开 / 播放最近录音 / 导出入口
```

这条主流程已经基本成立，是当前产品最重要的资产。

## 3. 完整性评估

| 模块 | 当前状态 | 完整度 | 说明 |
|---|---|---:|---|
| 核心录制 | 已成型 | 80% | 系统音频、进程音频、麦克风、混音均有实现；仍需更多真机回归和边界验证 |
| 音源选择 | 已成型 | 75% | “主目标 + 麦克风附加输入”的模型清晰；进程列表空态/权限失败态还可加强 |
| 录制反馈 | 已成型 | 70% | 有波形、电平、计时、轨道显示；录制中心视觉焦点仍被底部控制面板压缩 |
| 文件管理 | 基本可用 | 60% | 已有列表、Finder 打开、播放和导出入口；缺重命名、删除、定位目录、导出进度 |
| 格式能力 | 部分可用 | 45% | 底层支持 M4A/WAV；UI 未暴露格式选择；“生成 MP3”当前需要校准真实编码能力 |
| 快捷操作 | 缺失 | 25% | 缺菜单栏模式、快捷键、快速开始/停止、后台录制入口 |
| 发布体验 | 未完成 | 35% | 有构建/DMG 脚本，但缺完整 Release 检查、隐私说明、安装/权限引导文档 |
| SDK 对外能力 | MVP | 55% | Swift API 和 C API 已有骨架，但部分能力仍未完全落地，不能宣称完整 Web API 兼容 |

综合判断：

- 作为内部可用 Demo：已经比较完整。
- 作为 Beta 版：还差权限引导、稳定性验证、格式/文件闭环和错误状态。
- 作为公开发布产品：还需要发布包装、文案、隐私说明、下载/安装体验和核心路径回归测试。

## 4. 当前 UI 现状

当前 UI 采用 AppKit 自绘工业风：

```text
┌───────────────┬─────────────────────────────┐
│ Sidebar       │ Waveform + L/R Meter         │
│               ├─────────────────────────────┤
│ Record Target │ Tracks                       │
│ App List      ├─────────────────────────────┤
│ Mic Add-on    │ Transport Control            │
│ Saved Files   ├─────────────────────────────┤
│               │ Status Bar                   │
└───────────────┴─────────────────────────────┘
```

关键特征：

- 左侧是录制目标选择器，不再是并列 checkbox 配置器。
- 右侧上方是波形与 L/R 电平，中间是轨道监控，底部是硬件感 Transport Control。
- 视觉语言是深色金属、青色高光、红色录制按钮、等宽数字、网格背景。
- 当前生效 UI 规范是 `docs/designs/AudioRecordApp_Visual_Design_Spec.md`。

## 5. UI 设计评价

### 做得好的地方

1. 信息架构比早期方案清晰：用户先回答“录谁”，再决定“是否混入麦克风”。这比“系统音频 checkbox + 麦克风 checkbox”更符合用户心智。
2. 工业风视觉有记忆点：深色 surface、青色 glow、硬件按钮，比普通 macOS 表单更像专业录音工具。
3. 状态反馈比较完整：计时器、波形、电平、轨道列表、状态栏共同构成“正在录”的信任感。
4. 文件列表自绘是正确方向：避免系统默认白底/蓝选中态破坏整体暗色设计。

### 当前主要问题

1. 录制按钮不是绝对视觉中心。它在底部控制面板中，专业感强，但“一键开始”的直觉弱于中央大按钮。
2. 左右分栏适合专业工具，但对第一次用户略重。800x500 下侧边栏占掉 240px，主操作区显得紧。
3. 文件管理入口藏在侧边栏 Tab 中，录完后的“我下一步做什么”还不够强。
4. “生成 MP3”文案风险较大：如果实际输出不是标准 MP3 编码，会造成信任损伤。
5. 权限失败、进程列表为空、无录音文件等空状态需要更产品化，而不仅是技术提示。

## 6. 建议的产品取舍

### 当前主线不要变

继续坚持：

- 主目标：全部系统声音 / 指定 App 声音，互斥单选。
- 麦克风：作为附加输入，混入当前目标。
- 输出：优先单文件，降低用户理解成本。

这比“多轨录音台”更适合 MVP。

### 暂不建议立刻大改为垂直布局

`archive/design-proposals/tapture-ui-redesign.md` 的垂直方案有价值，但现在直接重构成本较高。更稳的路线是：

1. 先把当前左右分栏做到发布级。
2. 强化右侧录制区的视觉中心。
3. 后续根据用户反馈决定是否做“录制优先布局”。

## 7. 下一步路线

### P0：发布级闭环

1. 校准导出能力：要么实现真正 MP3，要么改文案为“导出 M4A/AAC”。
2. 增加权限引导：麦克风/屏幕录制权限缺失时给出明确修复路径。
3. 强化录完后的下一步：打开文件夹、播放、导出、删除/重命名至少补齐一部分。
4. 对系统音频、指定进程、混入麦克风三条路径做固定回归。

### P1：体验提效

1. 增加快捷键：开始/停止录制、打开文件夹。
2. 增加格式选择：M4A / WAV，MP3 视真实实现决定。
3. 增加菜单栏或快速入口，但不必第一版强做。

### P2：差异化增强

1. 定时录制 / 自动停止。
2. In-app 波形回放。
3. 多文件批量导出。
4. 更完整的 SDK / C API 示例。

## 8. 当前决策建议

短期不要再扩产品边界。下一阶段目标应该是：

> 把“录指定 App 声音 + 可混入麦克风 + 录完能立刻找到/播放/导出”这条链路打磨到稳定可信。

这条链路完成后，产品就具备 Beta 发布价值。
