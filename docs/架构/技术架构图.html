二、五条核心链路

① 录制(多源 / 多进程)

SidebarView / ControlPanelView选源:麦克风 / 系统 / 指定进程(可多选)· 开始
→

→
Enumerator → Tap → Aggregate → IOProc+ SilentKeepAlive + 麦克风环形缓冲混入
→

→

旁路:IOProc 回调同时分出 onLevel/onPeakLevel(电平表)与 onAudioBuffer(实时转写)——二者均在音频线程,消费方自行保证线程安全。

② 保存(录完 → 加密落盘)——目前整段写在 MainViewController

onRecordingCompleteAudioRecording(临时 M4A)
→
handleRecordingComplete0 秒 / 静音拦截(BUG-1)

→

→
AudioFileEncryptorAES-256-GCM → <uuid>.arlock
→
SecureDelete覆写删除临时 M4A
→
更新列表 → 进入编辑器失败则保留 M4A 兜底
.arlock 容器:Header 40B(magic ARLK · version · flags · key_id · audio_nonce · metadata_len)→ 元数据块(GCM) → 音频块(GCM)。密钥 = 固定主密钥 + 设备指纹派生(定位:版权保护层,非 DRM)。

③ 编辑(解密 → 内存 PCM → 命令栈 → 重编码回写)

→

四、边界现状 vs 目标

现状:一个 module,方向靠自觉

AudioRecordApp(表现 + 控制 + 编辑域 + 服务)
▼ 直接引用 Kit internal 类
build-app.sh:swiftc 平铺 Kit + App 所有 .swift → 同一 module
▼
AudioRecordKit(录制 + 加密 + 转写 + 工具 + AppKit 杂质)
另:SwiftPM 单独编译 Kit 仅为跑单测;API / CAPI 对外无真实消费者

建议目标:SwiftPM 多 target,编译器守边界

AudioRecordApp(UI + 控制,只依赖下列 public API)
▼
LoocapEditorCore(EditCommand / History / 片段模型 / 波形引擎,无 AppKit,可单测)
LoocapTranscribe(Engine 协议 + Apple 实现,可注入)
LoocapVault(.arlock / 密钥 / SecureDelete / 解密作用域 API)
AudioRecordKit(Capture:录制器 + ProcessTap + 权限 + 日志 + C API,零 AppKit)
Kit 对外 API 补齐 App 真实用到的能力(多源 / 进程 / mic 混入 / onAudioBuffer),App 自己吃自己的狗粮
