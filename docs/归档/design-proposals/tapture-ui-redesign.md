## 一、产品定位

**名称：** Tapture
**定位：** macOS 原生系统音频录制工具，核心技术壁垒是 Process Tap API（macOS 14.4+）
**目标用户：** 需要录制任意 App 音频的 Mac 用户（播客、会议录制、教程制作）
**设计方向：** 专业录音工具感，暗色主题，科技感

### 顶栏功能定义

| 按钮 | 功能 | Phase 2 状态 |
|------|------|-------------|
| [⚙ 设置] | 打开设置页面 | 灰显 + tooltip "设置（即将推出）" |
| [📁 文件管理] | 打开 Finder 到录音目录 | 完整实现 |

### 混音 checkbox 展示规则

- 仅当「系统音频」Chip 被选中时，在 Chip 下方 fade in 显示「↳ 混入麦克风」
- 取消选中系统音频时 fade out
- 不占用水平空间，不增加音源选择条高度（使用现有 padding 内空间）

### 导航流程

**主流程：**
打开 App → 音源 Chip 选择 → 点击录制按钮 → 录制中 → 停止 → 文件出现在底部列表

**进程录制流程：**
点击「📱 进程 ▾」→ Popover 向上弹出（锚定到进程 Chip 底部，避免被窗口底边截断）→ 显示当前运行的有音频的进程 → 选中进程 → 进程 Chip 显示 App 图标 → 开始录制

## 四、交互状态规格

### 4.1 全局录制状态

| 状态       | 视觉表现                                              | 录制按钮      |
|-----------|------------------------------------------------------|-------------|
| idle      | 背景静止，中央显示「选择音源，按下开始录制」灰色提示文字  | 冰蓝圆形 ●   |
| preparing | 按钮出现旋转加载环，状态文字「正在准备...」淡入淡出      | 禁用，旋转环  |
| recording | 背景随音量轻微呼吸（深色脉冲），波形冰蓝色活跃           | 灰色方形 ■   |
| stopping  | 背景呼吸渐退回静止，0.3s 过渡动画                      | 禁用         |
| playing   | 波形显示播放进度，底部文件行高亮                        | 禁用         |
| error     | 背景轻微红色渲染 + 顶部 banner 显示错误原因             | 冰蓝圆形（重试）|

### 4.2 各功能交互状态表

| 功能 | 加载中 | 空 | 错误 | 成功 | 部分 |
|------|--------|-----|------|------|------|
| 音源选择 | — | 3 Chip 未选中，idle 提示 | 进程列表刷新失败 → "无法获取应用列表，请重试" | Chip 选中，accent 描边 | 仅系统音频选中，麦克风未选 |
| 录制按钮 | preparing: 旋转环 | idle: 半透明+呼吸脉冲 | error: 红色+抖动 | recording: 方形停止钮 | — |
| 波形可视化 | preparing: 静态占位 | idle: 弱 sin 波占位 | — | recording: 实时声纹 | — |
| 进程下拉 | 刷新中: 旋转指示器 | "打开任意播放音频的 App，然后刷新" + [🔄刷新] | 权限缺失: "需要屏幕录制权限" + [去设置] | 进程列表展示 | — |
| 文件列表 | 文件元数据加载中 | "还没有录音文件" + 副文字 | 文件系统错误 → 底部 banner | 文件行列表 | — |
| 文件播放 | 播放缓冲中 | — | 文件损坏 → toast 提示 | 播放进度高亮行 | — |
| MP3 导出 | 导出中: 旋转+百分比 | — | 导出失败: toast | 成功: toast + Finder 打开 | — |

### 空状态规格

**空状态（无音源选择时）：**
- 波形区中央显示：`选择上方音源，然后按下录制`
- 字色：#94A3B8
- 录制按钮：半透明，不可点击

**进程列表为空时：**
- 显示：`打开任意播放音频的 App，然后刷新`
- 刷新按钮：小型 ghost 按钮

**进程权限缺失时：**
- 显示：`需要屏幕录制权限` + [去设置] 按钮
- 点击按钮跳转系统偏好设置 → 隐私与安全 → 屏幕录制

**文件列表为空时：**
- 显示：`还没有录音文件`
- 副文字：`录制完成后文件会出现在这里`

**导出进度：**
- 文件行内导出按钮替换为旋转指示器 + 百分比文字
- 导出完成：toast 提示 + 自动打开 Finder

## 五、用户旅程与情感弧

| 步骤 | 用户做什么       | 情感目标           | 设计支撑                    |
|-----|-----------------|--------------------|-----------------------------|
| 1   | 第一次打开       | 「这个 App 很专业」 | 暗色主题，干净全屏布局        |
| 2   | 选择音源 Chip    | 「我知道该怎么做」  | 3个 Chip，一目了然           |
| 3   | 点录制按钮       | 「开始了，有仪式感」 | 按钮形变动画 + 背景开始脉冲   |
| 4   | 录制进行中       | 「我在掌控」        | 波形呼吸 + 计时器跳动         |
| 5   | 停止录制         | 「完成了」          | 平滑过渡 + 文件出现动画       |
| 6   | 看到文件         | 「可以马上用」      | 文件行内直接播放/导出         |
| 7   | 想录进程音频     | 「在哪选 App？」    | 进程 Chip 带 ▾ 箭头暗示可展开 |
| 8   | 进程列表为空     | 「怎么没有？」→ 挫败 | 空状态给副文字 + 刷新按钮      |
| 9   | 录制中出错       | 「啊，坏了」→ 焦虑  | 红色 banner + 错误原因 + 重试  |

### 5 秒本能（第一印象）

暗色专业感 + 中央大圆按钮 → "这是一个录音工具"

### 5 分钟行为（核心流程）

选音源 → 录制 → 看文件 → 三步完成

### 5 年关系（长期信任）

稳定、不丢数据、快捷键肌肉记忆

## 六、响应式规格

### 6.1 窗口尺寸行为

| 窗口尺寸 | 录制中心区 | 音源选择条 | 文件面板 |
|---------|-----------|-----------|---------|
| **最小 800x500** | min-height: 280px，按钮+计时器可见 | 固定 88px | min-height: 100px（折叠到仅标题行），默认折叠 |
| **默认 800x600** | flex 55% ≈ 280px | 固定 88px | flex 25% ≈ 128px |
| **拖大 1000x800** | flex 55% ≈ 400px，波形更舒展 | 固定 88px | flex 25% ≈ 180px，更多文件行可见 |
| **极宽 1200x600** | 水平居中 max-width: 900px | 跟随居中 | 跟随居中 |

**关键 resize 规则：**
1. 录制中心区和文件面板按比例伸缩，音源选择条固定高度
2. 窗口高度 < 550px 时，文件面板自动折叠
3. 窗口宽度 > 1000px 时，内容区水平居中（max-width），不无限拉宽
4. 不允许水平方向低于 800px（`window.minSize = NSSize(width: 800, height: 500)`）

### 6.2 文件面板折叠交互规格

| 属性 | 规格 |
|------|------|
| 折叠触发 | 标题行右侧 ▾/▴ 按钮，44px 点击区域 |
| 展开高度 | flex 25% 或 min 120px |
| 折叠高度 | 44px（仅标题行） |
| 动画时长 | 0.25s ease-in-out |
| 动画方式 | 窗口高度不变，录制中心区吸收释放的空间 |
| 状态记忆 | 折叠状态在窗口生命周期内持久 |
| 首次启动 | 默认展开（让用户知道有文件区域），之后记忆状态 |

## 八、已解决的设计决策

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| 1 | 混音 checkbox 在水平 Chip 条下方如何展示？ | 系统音频 Chip 下方缩进显示，仅选中时 fade in/out 出现 | 保持功能完整，不增加水平空间 |
| 2 | 文件面板默认折叠还是展开？ | 首次启动展开（让用户知道有文件区域），之后记忆状态 | 空状态也需要被看到，建立预期 |
| 3 | 顶栏的 [⚙] 按钮打开什么？ | Phase 2 先不实现设置页，按钮灰显 + tooltip "设置（即将推出）" | 避免死链接 |
| 4 | TabContainerView 删除后切换逻辑怎么处理？ | 纯删除，所有内容同时可见（垂直布局的优势） | 无需切换 = 减少交互步骤 |
| 5 | 进程 Popover 在水平布局中锚定到哪？ | 锚定到进程 Chip 底部，向上弹出 | 底部空间有限，向上更安全 |

## 九、实现优先级

1. **全局主题** — 应用 #0F172A 背景，建立暗色基调
2. **录制中心区重排** — 波形全宽 + 计时器 + 按钮居中
3. **音源 Chip 组件** — 替换现有侧边栏复选框
4. **状态视觉** — 6个状态的颜色/动画
5. **文件列表** — 底部折叠式，行内操作
6. **进程下拉** — 进程选择 UI 重构
7. **空状态** — 各场景空状态文案+图示
