# FIX-017 录制中锁源 · 需求规格

> 状态：**已审核**（2026-11-04 老板「开工吧」；默认采纳修法 ①）。TODOS.md 池行为状态真相；本文是验收与边界正本。
> 范围：**仅 ① 录制期间锁源**（把已有 `SidebarView.isRecordingLocked` 接到录音态）。②③ 明确非本单。

---

## 一、背景 / 实证

### 现象（2026-10-28 22:39）

Ready 态点录制时侧边栏仍为默认「系统混音」；开录约 1.6s 后点选 TencentMeeting → 侧边栏/顶栏 UI 跟选应用，**整场实际管线仍是 systemMixdown**。用户以为在录 A，实际录 B。

同场亦见 FIX-016 备注：实录走 systemMixdown + 开麦后才选 TM，与本单同源（选源未进管线）。

### 代码事实（审读结论，开工前）

1. `SidebarView.isRecordingLocked`（`SidebarView.swift`）在系统混音行与进程行点击路径上有 `guard !isRecordingLocked else { return }`，**全工程无赋值 `true`**——锁源是半成品。
2. 录音中改源：`mainWindowViewDidSelectProcesses` 只改 `selectedPIDs` / UI 模式文案，并调用 `setCoreAudioTargetPID`；录制器侧 `setTargetPID` **只写字段、不重建 Process Tap**，活跃管线不变。
3. 开录走 systemMixdown 时，活跃录制器往往不是 process Tap 实例，`setCoreAudioTargetPID` **碰不到本场管线**。
4. 进程退出监控（`checkSelectedProcessStillAlive` / `setupProcessExitMonitoring`）读的是**当前** `selectedPIDs`：若录音中 UI 源与管线脱节，监控可能盯错目标（误停或不停）。锁源可把「本场选源」钉死，与管线对齐。

## 二、目标行为

1. **开录前**：侧边栏可选系统混音 / 应用进程；开录瞬间的选源决定本场管线（既有行为，不回归）。
2. **录音态**（`preparing` / `recording` / `stopping`）：侧边栏源选择**禁用或无效**——点选不改 `selectedPIDs`、不触发源切换回调、不调用 `setCoreAudioTargetPID` 改本场意图。推荐接线：录音态置 `sidebarView.isRecordingLocked = true`。
3. **停录后**（`idle`；以及 `playing`）：解锁，可再改源，供下一场开录使用。
4. **本单不实现**录音中热切源并重建 Tap/聚合设备（见非目标）。

## 三、非目标（已知边界）

| 项 | 说明 | 处置 |
|---|---|---|
| ② 启动恢复上次选中源 | 冷启仍默认系统混音，不恢复上次进程 | **另开后续单**；本单不写持久化/恢复 |
| ③ 顶栏「Selected Source」与实际管线源一致 | 顶栏仍可能跟侧边栏 UI，而非本场 Tap 真相 | **另开后续单** |
| 录音中热切源重建管线 | 对等 FIX-021「切麦=生效」的进程源热切换 | **明确不做**；本单只锁，不重建 |
| 麦克风设备切换 | FIX-021 已拍板并交付「切麦=生效」 | 不动；勿与本单混淆 |

**命名冲突提示**：`docs/归档/TODOS-done-2026-11.md` FIX-021 正文曾写「录音中切麦不生效（FIX-017 同族）」——那是麦设备口径，**不是**本单的进程/系统混音源锁定。本单正本以本文 + 池行标题为准。

## 四、验收标准（可自验；硬证据优先）

- [ ] **a. 锁生效**：开录进入 `preparing`/`recording` 后，`SidebarView.isRecordingLocked == true`（或等价：侧边栏点选不改 `selectedPIDs`、不触发 `sidebarViewDidSelectProcesses` / `mainWindowViewDidSelectProcesses`）。
- [ ] **b. 解锁**：停录到 `idle`（及进入 `playing`）后 `isRecordingLocked == false`，可再改源；再开录按新选源建管线。
- [ ] **c. 开录瞬间选源仍生效**：开录前选进程或系统混音，本场落盘/日志中的源与开录瞬间一致（不因中途误点而变）。
- [ ] **d. 构建**：`bash build-app.sh` exit 0。
- [ ] **e. SDK 单测不回退**：`bash scripts/test_sdk.sh`（或适配层等价：`cd AudioRecordKit && swift test --disable-sandbox`）全绿，基线不降。
- [ ] **f. 接线证据**：日志或代码路径证明录音态传播到侧边栏锁——例如 `MainWindowView.updateRecordingState`（或 Controller 等价路径）在 `preparing`/`recording`/`stopping` 置锁、`idle`/`playing` 解锁；可用 App 日志「UI 状态机」行 + 锁赋值点对照，或静态 diff 引用。

实机建议（交付验收可选用，非阻塞自测）：开录后狂点其它应用行，侧边栏选中态与 `selectedPIDs` 不变；停录后再点可变。

## 五、实现要点（非强制处方）

1. **接线点**：`MainWindowView.updateRecordingState(_:)` 已是 UI 状态机汇合点（现只推 ControlPanel）；在此（或 `MainViewController` 调用处）按态设置 `sidebarView.isRecordingLocked`：
   - 锁：`.preparing` / `.recording` / `.stopping`
   - 解锁：`.idle` / `.playing`（及 `.error` 回到可交互时）
2. **半成品补全**：优先复用现有 `isRecordingLocked` 守卫；若需灰显/禁用鼠标，可在同属性 didSet 里刷新行交互态（可选增强，验收 a 以「点了不变」为准）。
3. **进程退出监控**：锁源后 `selectedPIDs` 应继续代表本场管线目标；实现时**不要**在锁态清空或改写 `selectedPIDs`，以免 `checkSelectedProcessStillAlive` / `didTerminateApplication` 误伤。
4. **勿扩 scope**：不要在本单加 UserDefaults 恢复上次源、不要改顶栏 Selected Source 文案逻辑、不要做 Tap 热重建。
