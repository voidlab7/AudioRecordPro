## 二、质量观察（真实录音 C 卷）

- **能打的**：口语流完整、长句逻辑连贯、「漫长的季节」「救猫咪」「小红书」等实体全部正确；多人对话无说话人分离（预期内，云端方案才有的能力）
- **典型短板**：同音字错（「高光」→「胡光」、「全景声/场景搭建」类词偶有误）、标点基本被剥（只有零星逗号）、语气词保留较多（呃/嘛/啊）
- **对产品的含义**：转写质量已达「可用草稿」级；标点恢复和语气词清理可在 S1/S3 后处理层解决（NaturalLanguage 框架或轻量规则），不影响引擎选型

## 三、工程事实（给 S1 抄作业）

1. yap 源码构建可用：`swift build -c release --disable-sandbox`（WorkBuddy 沙箱内 brew / SwiftPM 默认 sandbox-exec 全被拦，`--disable-sandbox` 是绕行钥匙——与 LOOP-05 的 xcodebuild 问题同根）
2. 首跑无需手动下载 zh-CN 资产（系统已有），冷启动 ~2s 为进程+allocate 开销
3. yap 用的就是 S1 要集成的 SpeechAnalyzer/SpeechTranscriber 路径，S1 可直接参考其源码（/tmp/yap-src，CC0）
4. App 内录音是 .arlock 加密存储（AudioFileEncryptor）→ S1 转写管线需要从内存/解密后 buffer 进引擎，或先走导出文件路径
