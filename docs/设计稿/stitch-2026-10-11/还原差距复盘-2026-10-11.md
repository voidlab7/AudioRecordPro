# UI-003 还原差距复盘：开发过程缺失了什么信息

> 2026-10-11 深夜 · Tab 复盘 · 触发：老板指出「无法做到完全还原设计稿」

## 一、直接证据：本轮踩过的三类坑

| 坑 | 实例 | 根因 |
|---|---|---|
| 色值猜错 | 第一版选中行用 #10B981→#0B815A 饱和渐变，设计实测 **#56B8A4 柔和薄荷纯色** | 只拿到位图，没有色值标注；开发凭「品牌翡翠」先验推色 |
| 单点采样采错 | 胶囊第一次采样得 #202F2E——实际采到的是「Selected Source:」文字与胶囊之间的**间隙底色**；设计真身是**薄荷实底胶囊+深色文字** | 采样方法脆弱：单像素点无区域聚类，撞上文字/间隙就错 |
| 形态学差异整组漏掉 | 设计有：每行右侧 radio 圆圈、选中行副标题「Focused App Capture」、SYSTEM AUDIO/APP AUDIO 大写小灰字 section header、RECORD 凸起 pill 分段控件、侧栏宽 31% | 拆解文档是**区块级**（标题栏/侧栏/画布），不是**元素级**，形态细节根本没进 checklist |

## 二、缺失的信息（按致命度排序）

1. **设计规格源缺失（最致命）**：Stitch 产出 = 位图 PNG + 一段 md，没有 Figma 源文件 / Design Tokens / 标注导出。
   → 色值、间距、字号、字重、圆角、透明度全部无真值，只能逆向采样。
2. **元素级对照清单缺失**：开工前的「设计拆解与现状差异分析.md」停留在区块级。radio/tile/header/副标题条件/分段控件形态这类「有或没有」的差异，没有一张穷举表 → 无从谈还原。
3. **状态矩阵缺失**：设计稿只画了「企业微信选中」这一个状态。未选中 / hover / 系统声音行选中 / 无选中 多种状态的样式无参考 → 我自行发挥（渐变、白字✓），与设计语言脱节。
4. **布局契约缺失**：设计 1080px 宽下侧栏占 31%；实现窗口 1200px 侧栏定宽 ~200px（≈17%）。比例关系没有约定，整体密度感就不同。
5. **自验基准缺失**：验收标准写「老板肉眼核对通过」，没有定义交付物里必须有「并排截图 + 逐元素对照表」→ 第一版「整体看着像」就交了，把像素级 diff 的工作转嫁给了老板的眼睛。

## 三、结论

不是执行不认真，是**信息链断了两截**：
- 设计 → 开发：只有图，没有规格（色值/间距/状态/布局契约）。
- 开发 → 验收：只有「像不像」，没有可校验的 diff 基准。

## 四、流程固化（下一步落地）

1. **开工前置**：设计 PNG 必须先跑「规格提取」——区域取色聚类（非单点）+ 元素级穷举表（含状态矩阵），落盘为单子附件，老板过目后才开工。
2. **自验前置**：实现截图与设计稿**并排 diff + 像素抽样报告**先行，作为 self-verify 的硬证据，老板只做终审。
3. **工具化**：取色/网格探测脚本固化 `scripts/design_probe.py`（本轮临时脚本已验证有效）。
