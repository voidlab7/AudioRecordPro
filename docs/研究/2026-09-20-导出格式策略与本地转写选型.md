# 导出格式策略与本地转写选型（2026-09-20 调研）

> 背景：老板问「海外 macOS 用户用什么音频格式 / 要不要 MP3 / 能否内置 Whisper」。
> 本文沉淀该次讨论的三块结论：① 海外市场格式习惯与导出策略；② 本地转写（Whisper 系）选型；③ 两条技术线的边界。
> 决策状态：格式策略已定方向，转写线未立项（候选 V1.3）。

## 一、海外 macOS 市场的音频格式习惯

| 人群 | 主用格式 | 原因 |
|---|---|---|
| 普通用户（备忘/会议/语音） | **M4A (AAC)** | Apple 全家桶默认：Voice Memos、QuickTime、iMessage 全是它 |
| 播客主/内容创作者 | **MP3** | 播客分发事实标准（Apple Podcasts / Spotify 全吃），通用性天花板 |
| 音乐人/后期 | **WAV** | 丢进 Logic/DAW 的无损交接格式；AIFF 已被 WAV 边缘化 |
| 发烧友 | FLAC | 无损存档，小众 |
| OGG/OPUS | 几乎无人主动要 | Linux/Web 场景，macOS 桌面无感 |

三条主流链路：**语音备忘 → M4A；做播客 → MP3；做音乐 → WAV**。

## 二、导出格式策略（已定方向）

**三个格式分层：M4A 当默认、WAV 管专业、MP3 管通用——MP3 必须留。**

| 格式 | 定位 | 技术实现 | 成本 |
|---|---|---|---|
| **M4A (AAC)** | **默认导出**。Apple 生态无缝，与竞品（MacWhisper 等）一致 | AAC 直通/原生编码，零外部依赖、零 License 风险 | 零 |
| **MP3** | 分享首选（发别人/传 Windows 的安全牌），手选率预计最高 | ExtAudioFile Apple 软件编码器，**零依赖**（已实现） | 零 |
| **WAV (PCM)** | 专业用户闸门：无损 48kHz 交出 | AVAudioFile 原生（已实现） | 零 |
| FLAC | 进阶存档 | AudioToolbox 原生支持（kAudioFormatFLAC, macOS 10.13+），可去 ffmpeg 化 | 小 |
| OGG | **重新考虑** | Apple 无 Vorbis，是唯一真依赖 ffmpeg 的格式 | 大 |

### ⚠️ OGG 决议变更（待拍板）

2026-09-17 曾决议「保留 OGG」（理由：反正要集 ffmpeg 静态库）。但按海外市场事实，OGG 需求趋近于零——**若砍掉 OGG，ffmpeg 可整体出仓**，节省静态库集成约 2.5 天工期与 8-15MB 体积，License 问题连根拔除。此决议等待老板拍板后更新 REQ-1.2-01。

### 导出卡片格式排序

```
格式下拉默认:  M4A (AAC)   ← 默认选中
              MP3          ← 分享首选
              WAV (PCM)    ← 无损/专业
              FLAC         ← 进阶

```

## 三、本地转写选型（Whisper 系，候选 V1.3）

### 候选方案对比

| 方案 | 本质 | 塞进 Swift 工程难度 | Apple Silicon 优化 | License |
|---|---|---|---|---|
| Faster-Whisper | Python 推理层（CTranslate2 重实现，比原版 Whisper 快约 4 倍、省一半内存） | ❌ 差（要带整套 Python 运行时） | 好 | MIT |
| **whisper.cpp** ⭐ | 纯 C/C++（GGML） | ✅ **最好**：C API 可被 Swift 直接桥接，可编静态库 | Metal GPU 加速 | MIT |
| MLX Whisper | Apple 官方 MLX 框架 | ✅ 好（有 Swift 版 mlx-swift-examples） | 最原生 | MIT |

**结论：内置转写选 whisper.cpp**——它就是社区为「本地内置」场景准备的（MacWhisper、superwhisper 等知名 Mac 转写 App 底层全是它）。Faster-Whisper 适合 Python 服务端/脚本场景，不适合原生 App。

### 集成形态（若立项 V1.3）

```
AudioRecordApp
├── WhisperKit 层
│   ├── whisper.cpp 静态库（~几 MB，不捆模型）
│   ├── WhisperService.swift：arlock 解密 → WAV PCM → C API 转写
│   └── 模型管理：App 内不预装，首次使用按需下载 GGML 模型
│       tiny ~75MB / base ~142MB（推荐默认）/ small ~466MB / large-v3 ~3GB
```

与现有架构的衔接点：
- **输入**：`.arlock` 解密后即标准音频，可在录制完成时自动触发转写
- **时间戳**：whisper.cpp 原生输出分段/词级时间戳 → 可做「点字幕跳转播放」（剪映式体验的杀手级功能）
- **隐私卖点**：完全本地推理，「录音不出设备」本身是录音 App 的差异化卖点
- **License**：Whisper 权重 MIT + whisper.cpp MIT，商用/上架零障碍
- **⚠️ 重采样**：whisper.cpp 吃 16kHz PCM，录音是 48kHz——用 Apple 原生 `AVAudioConverter` 重采样即可，**不需要为此动 ffmpeg**
- **排期建议**：新功能线，放 V1.2 格式转换线之后；第一步 spike = whisper.cpp 静态库编译 + base 模型 + 转写一条 20s 录音（约半天验证整条链路）

## 四、两条技术线的边界（铁律）

| 线 | 管什么 | 工具 | 明确不管 |
|---|---|---|---|
| **格式线**（V1.2） | 格式转换、导入导出、批处理、响度归一化 | ExportService + ffmpeg LGPL 静态库（若 OGG 保留） | 不碰实时 DSP |
| **转写线**（V1.3 候选） | 音频 → 文字（转写/字幕/搜索） | whisper.cpp 静态库 | **不做格式转换** |
| **编辑器 DSP 线** | 波形渲染、裁剪、淡入淡出、EQ、实时监听 | AVAudioEngine + vDSP + AudioUnit | 不碰 ffmpeg |

- whisper.cpp **只做「音频 → 文字」**，不做格式转换（其内部解码仅供自己消费，不对外输出音频文件）
- 两条线并列而非替代：ffmpeg 管格式广度，whisper 管内容理解，谁也替不了谁
- 功能层可叠加：录完音后双支线——ExportService 出格式文件；whisper 出文字+时间戳 → 字幕跳转 / SRT 导出 / 全文搜索录音
