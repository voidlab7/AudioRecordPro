## 二、FLAC 原生路线验证（保留 FLAC 的依据）

macOS 26.2 SDK 的 Swift overlay **未导出** `kAudioFormatFlac` 常量（编译实证 `cannot find in scope`），但 CoreAudio 库层完整支持：

1. `afconvert -f flac -d flac`：系统工具实测产出合法 FLAC（afinfo：File type ID flac / 44.1kHz）
2. `AVAudioFile` + 四字符码 `0x666C6163`（'flac'）：写出标准 FLAC bitstream，**afinfo 完整识别 24bit/44.1kHz/72769 samples**（探针 `/tmp/rel006_av2.flac`，临时文件）
3. **关键坑（已固化为代码注释+TC-004 断言）**：AVAudioFile 产物 finalize 发生在对象 deinit（26 SDK 移除 `ExtAudioFileClose` 链接符号，探针链接阶段 `Undefined symbol _ExtAudioFileClose` 实证）。未 finalize 的 FLAC 流 afinfo 报 `AudioFileOpenURL failed`（探针 av1 复现）→ transcode 写块收进独立 `do {}` 作用域，出块即释放再读产物。
4. 实现处：`ExportService.swift` 顶部 `kAudioFormatFlac` 常量（带注释）+ `.flac` case settings（无码率 key，CoreAudio 自动按源精度 16/24bit）
