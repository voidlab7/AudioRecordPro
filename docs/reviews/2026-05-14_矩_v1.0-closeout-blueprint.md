## 1. REQ-1.0-11 异常处理补全

### 现状
- `FileManagerUtils` 已有：磁盘空间查询、crash 标记/恢复 API（上轮已添加）
- `StatusBarView` 已有：磁盘空间显示
- **缺失**：录制前检测 + 录制中周期监控 + crash 恢复弹窗 + 睡眠阻止

### 方案

#### 1.1 磁盘空间保护（MainViewController）
- **录制前**：`startRecording()` 开头调用 `fileManager.hasSufficientDiskSpace()`，不足则弹 `NSAlert` 警告并阻止录制
- **录制中**：启动 `diskMonitorTimer`（每 10 秒检测），低于 100MB 时自动调用 `stopRecording()` 并弹窗提示
- **不改 SDK 层**——保护逻辑在 App 层，SDK 不关心磁盘

#### 1.2 Crash 恢复（AppDelegate）
- `applicationDidFinishLaunching` 中调用 `fileManager.checkForUnfinishedRecording()`
- 发现未完成文件 → 弹 `NSAlert`（"发现未保存的录音 XX:XX，是否恢复？"）
- 用户点"恢复" → `fileManager.recoverRecording(from:)` → 加入文件列表
- 用户点"丢弃" → 删除临时文件
- **录制标记时机**：`startRecording()` 成功后调 `markRecordingStarted()`，`handleRecordingComplete()` 和 `stopRecording()` 后调 `markRecordingFinished()`

#### 1.3 睡眠阻止（MainViewController）
- 录制开始时：`IOPMAssertionCreateWithName(kIOPMAssertPreventUserIdleSystemSleep, ...)`
- 录制停止时：`IOPMAssertionRelease()`
- 需要 `import IOKit.pwr_mgt`

#### 改动文件
- `AudioRecordApp/Sources/Controllers/MainViewController.swift` — 磁盘监控 + 睡眠阻止 + 录制标记
- `AudioRecordApp/Sources/App/AppDelegate.swift` — crash 恢复弹窗

## 2. REQ-1.0-10 设置页面

### 方案
- 新建 `AudioRecordApp/Sources/Views/SettingsWindowController.swift`
- 使用 `NSWindow` + `NSTabView` 实现标准 macOS 偏好设置窗口
- 从 `AppDelegate` 添加 Cmd+, 菜单项打开
- 设置项通过 `UserDefaults` 持久化

### 设置项
| 设置项 | key | 类型 | 默认值 |
|--------|-----|------|--------|
| 录制格式 | `recordingFormat` | String | "m4a" |
| 采样率 | `sampleRate` | Int | 48000 |
| 存储位置 | `recordingsDirectory` | String | ~/Documents/AudioRecordings/ |
| 开机启动 | `launchAtLogin` | Bool | false |
| 录制快捷键 | `recordShortcut` | String | "Cmd+R" |

### 改动文件
- 新建 `AudioRecordApp/Sources/Views/SettingsWindowController.swift`
- `AudioRecordApp/Sources/App/AppDelegate.swift` — 添加设置菜单项 + Cmd+,
- `AudioRecordApp/Sources/Controllers/MainViewController.swift` — 读取 UserDefaults 设置

## 决策摘要

| # | 决策 | 理由 |
|---|------|------|
| 1 | 磁盘保护在 App 层不在 SDK 层 | SDK 是录制引擎，不应耦合 UI 弹窗逻辑 |
| 2 | 设置页面用 NSWindow 不用 SwiftUI | 项目全 AppKit，保持一致 |
| 3 | 单实例检测在 main.swift 最早时机 | 避免初始化任何资源后才发现重复 |
| 4 | 睡眠阻止用 IOPMAssertion 不用 NSProcessInfo | IOPMAssertion 更精确可控 |
