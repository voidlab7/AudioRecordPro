## 实现：状态机文案驱动 → 枚举通道（14 文件 +129/-58）

### 解耦设计

根因链：`Recorder.onStatus(String 本地化文案)` → Controller → `updateStatus(String)` / `containsStatusFailure()` / CAPI `contains("录制中")` ——**状态用字符串广播，逻辑靠文案猜**，非中/英系统语言下全部失效。

修复：新增**结构化状态通道 `onStateChange: ((RecordingState) -> Void)?`**（复用 Kit 现成 public 枚举），文案通道降级纯展示：

| # | 位置（报告 §四） | 解耦后 |
|---|---|---|
| 1 | `StatusBarView.updateStatus(String)` contains 猜状态 | **猜测逻辑删除**，纯展示；状态灯只认 `updateRecordingState(枚举)`（主状态机 16 处枚举调用本就存在，前轮已铺） |
| 2 | `MainViewController` containsStatusFailure → handleRecordingFailure | 桥改双通道：onStatus 纯展示 + onStateChange 驱动状态机与错误处理；`containsStatusFailure()` helper 删除（引用清零） |
| 3 | `AudioRecordSDK_C` contains("录制中"/"准备"/"停止") → stateValue | 改订阅 onStateChange，映射抽公共 `RecordingState.capiStateValue`（**数值契约 0-3 维持不变**，App 内部零使用 C API 已核实） |
| 4 | `MicrophoneRecorder` catch 内 contains("permission"/"权限"/"denied") | **权限预检前置**：start 前 `AVCaptureDevice.authorizationStatus(for: .audio)` 确定性拦截（未授权→.error+权限提示+return）；catch 删文案匹配走通用失败 |

配套：协议+Base 加 onStateChange（发射点伴发 .recording/.error/.stopping/.idle，13 处中状态语义明确的 10 处标注，模糊处不发）；AudioRecordAPI/AudioRecorderController 转发；`AudioRecordKit/Tests/SDKErrorAndConstraintsTests` Mock 补协议属性。
