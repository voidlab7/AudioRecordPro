七步循环体

    下发与验收：两个上下文

    同一上下文既下发又验收，实现方的自我陈述会污染判断。所以同一张单，下发与验收是两个独立会话，唯一共享通道是落盘工件。

    下发上下文PM → Tab

    ✓ 只给 spec：要什么 / 怎么算对
    不含实现偏好
    不含对话过程
    隔离墙

    验收上下文PM 复核

    ✓ 只读 判据 ＋ 硬证据
    禁读 Tab 的实现陈述
    不共享对话记忆

    发现偏差 → 不改话、改单：回池开 FIX 单重新下发，偏差原因写进反哺。PM 自身漂移的兜底：A 类硬判据 → B 类老板审核 → 老板最终验收，三层。

    07

    怎么知道它在正常转

    循环没有常驻进程，所以不盯进程，盯痕迹的新鲜与自洽。最危险的是“静默停摆”——该跑的一轮没跑。体检结果每天 08:30 嵌进晨报首段。

    loopbuddy_health.py · 只读 · exit 0 / 1 / 2当前判定 ● 健康，循环在转

    维度 1心跳

    最新战报的新鲜度。>48h 警告，>96h 失败

    维度 2自洽

    战报写 PASS 但证据列为空 → 判失败，防自我合理化

    维度 3证据新鲜度

    单测日志不能比战报旧，不能带失败，防拿旧绿灯冒充

    维度 4完整性

    战报之后 master 源码零直达提交，防绕过 worktree

    监控读原始证据，不读结论。战报是被检查的对象而不是证人——判据来自 git 提交链、测试日志、文件时间；监控只读、不改状态、告警必带下一步。
