# REQ-2.0-06 多应用同时录音 + 多轨道显示

## 版本：V2.0 | 优先级：P0 | 状态：⬜ 待开发

## 背景

当前录制模式只支持"全部系统声音"混录或单个进程录制。用户无法同时选择多个应用独立录制。竞品 Audio Capture Pro 已支持多应用勾选 + 多轨道同时录制显示，我们需要补齐这一核心能力。

参考竞品：Audio Capture Pro（¥128/年）— 左侧多选应用列表，右侧多轨道实时波形显示。

## 核心需求

支持用户在侧边栏同时勾选多个应用，每个应用独立录制为一条轨道，录制过程中主区域显示所有轨道的实时滚动波形。

## 1. 侧边栏改造：单选 → 多选

### 当前行为

- 应用列表为**单选**（点击切换高亮）
- 选中某个应用 = 录制目标切换为该应用
- 不选任何应用 = 默认"全部系统声音"

### 改造后行为

- 每个应用行增加 **Checkbox**，支持多选
- "全部系统声音"行也带 Checkbox，可与应用共存
- 麦克风行保持独立 Checkbox（作为独立轨道）
- 勾选多个应用 = 每个应用独立录制为一条轨道

### 交互规则

| 操作 | 结果 |
|------|------|
| 勾选 1 个应用 | 单轨道，波形铺满整个区域（当前行为） |
| 勾选 N 个应用 | N 条轨道，波形区等分显示 |
| 勾选 0 个应用 | 默认"全部系统声音"（当前行为） |
| 勾选"全部系统声音" + 应用 | "全部系统声音"为一轨 + 各应用各一轨 |
| 勾选麦克风 | 麦克风作为独立轨道加入 |
| 录制中 | 锁定选择，不允许增减勾选 |

### 最大轨道数限制

- 最多同时录制 **5 条轨道**（含麦克风）
- 超过 5 个时提示："最多同时录制 5 个音源"

## 2. 多轨道波形显示

### 核心规则

**轨道数量 = 选中的音源数量，轨道区域始终被等分填满。**

| 选中音源数 | 轨道布局 |
|---|---|
| 1 个 | 单轨道**铺满**整个波形区域 |
| 2 个 | 2 条轨道，各占 50% 高度 |
| 3 个 | 3 条轨道，各占 33% 高度 |
| N 个 | N 条轨道等分高度 |
| 超过 5 个 | 不允许（限制最多 5 轨） |

### 每条轨道内容

```
┌──────────────────────────────────────────────────────────────┐
│  [AppIcon] Chrome        🔴 录制中                           │
│  ┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃→    │
│  ─────────────────────── 中线 ───────────────────────────     │
│  ┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃→    │
└──────────────────────────────────────────────────────────────┘
```

每条轨道包含：
- 左上角：应用图标 + 应用名称
- 右上角：录制状态指示（🔴 红点）
- 中间：实时滚动波形（从左向右滚动）
- 中线：水平参考线

### 无时间刻度

录制态波形为实时滚动模式（类似示波器），不需要时间刻度。时间刻度仅在编辑态使用。

### 轨道选中

- 点击某条轨道 → 该轨道高亮（左侧蓝色竖条）
- 右侧电平表切换为显示选中轨道的电平
- 默认选中第一条轨道
- 选中不改变布局，所有轨道始终同时可见

## 3. 多进程并行录制引擎

### 当前架构

`AudioRecorderController` 使用 `activeRecorders: [AudioSourceType: AudioRecorderProtocol]` 字典管理录制器。`AudioSourceType` 枚举只有 3 种：`.microphone`、`.systemAudio`、`.specificProcess`。

### 改造方案

需要支持多个 `.specificProcess` 实例同时工作：

**方案 A（推荐）**：将 key 从枚举改为字符串标识符

```swift
// 改造前
var activeRecorders: [AudioSourceType: AudioRecorderProtocol] = [:]

// 改造后
var activeRecorders: [String: AudioRecorderProtocol] = [:]
// key 示例: "process_12345", "process_67890", "microphone", "system"
```

**方案 B**：保持枚举但增加关联值

```swift
enum AudioSourceType: Hashable {
    case microphone
    case systemAudio
    case specificProcess(pid: pid_t)
}
```

### 每条轨道独立录制

- 每个选中的应用创建独立的录制器实例
- 每个录制器写入独立的音频文件
- 每个录制器独立回调电平数据
- 录制完成后生成 N 个独立文件

### 技术风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 多 Process Tap 并行 | macOS ScreenCaptureKit 是否支持同时对多个 PID 建立独立 tap | 需技术 Spike 验证 |
| I/O 性能 | 3-5 路 48kHz/32bit 同时写入 | 异步 I/O + 独立写入队列 |
| 电平回调压力 | 每路每帧回调 | 节流合并，按选中轨道分发 |

## 4. 轨道板联动

### 当前行为

`TrackPanelView` 已支持多行轨道显示（Mute/Solo 按钮），但数据来源是静态的 `TrackInfo` 数组。

### 改造后行为

- 轨道板行数 = 选中音源数量
- 每行显示：应用图标 + 名称 + Mute + Solo
- Mute 某轨道：该轨道录制继续但不播放（预留，录制时无意义）
- Solo 某轨道：电平表只显示该轨道（等同于选中）

---

## 5. 录制完成后行为

- 录制停止后，生成 N 个独立音频文件
- 文件命名规则：`{时间戳}_{应用名}.m4a`
  - 示例：`2026-05-27_14-30-00_Chrome.m4a`
  - 示例：`2026-05-27_14-30-00_QQ Music.m4a`
  - 示例：`2026-05-27_14-30-00_Microphone.m4a`
- 所有文件归入同一录制组（共享时间戳前缀）
- 进入编辑态时加载所有轨道文件（V2.1 多轨编辑器）
- V2.0 MVP：录制完成后进入第一条轨道的编辑器

## 6. 边界情况

| 场景 | 处理方式 |
|------|---------|
| 录制中某个应用退出 | 该轨道标记为"已断开"（灰色），停止录制该轨道，已录部分保留，其他轨道继续 |
| 录制中应用无声音 | 正常录制静音数据，波形显示为平线 |
| 只勾选 1 个应用 | 退化为当前单进程录制行为，波形铺满 |
| 勾选 0 个应用 | 默认"全部系统声音"（当前行为） |
| 磁盘空间不足 | 所有轨道同时停止，已录部分保留 |
| 某轨道写入失败 | 该轨道停止，其他轨道继续，提示用户 |
