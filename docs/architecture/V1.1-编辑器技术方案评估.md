## 二、架构决策

### AD-01: Content 区页面切换——容器视图方案

**方案对比：**

| 方案 | 优点 | 缺点 | 评估 |
|------|------|------|------|
| A) NSTabView 切页 | 系统组件，稳定 | Tab 标题占空间，与 Industrial 风格冲突 | ❌ |
| B) 手动 isHidden 切换 | 简单 | 两套视图同时存在，内存浪费 | ⚠️ 可接受 |
| C) 容器视图 + addSubview/removeFromSuperview | 干净，不用视图不占内存 | 切换时需重建约束 | ✅ 推荐 |

**决策：方案 C — 容器视图。**

实现细节：
1. 在 `MainWindowView.contentView` 中增加一个 `contentContainerView` 作为 wrapper
2. 当前所有子视图（WaveformView、ControlPanelView 等）包裹进 `recordingContentView`
3. 编辑器视图放入 `editorContentView`
4. 切换时：remove 当前视图，add 目标视图，播放 200ms 动画

```swift
// 伪代码
func showEditor(for file: RecordedFileInfo) {
    guard !isRecording else { return } // 录制中不允许进编辑器
    recordingContentView.removeFromSuperview()
    contentContainerView.addSubview(editorContentView)
    pinToEdges(editorContentView, in: contentContainerView)
    // 动画: 从右滑入
    editorContentView.animator().alphaValue = 1.0
}

func showRecording() {
    editorContentView.removeFromSuperview()
    contentContainerView.addSubview(recordingContentView)
    pinToEdges(recordingContentView, in: contentContainerView)
}
```

**风险评估：** 低。AppKit 的 addSubview/removeFromSuperview 是标准操作。约束固定用 helper 函数封装。

### AD-02: 编辑器控制器分离

**决策：新建 `EditorViewController`，从 `MainViewController` 分离编辑逻辑。**

```
MainViewController (精简)
├── 录制管理（保持现有）
├── 播放管理（保持现有）
├── 文件管理（保持现有）
└── 编辑器入口（仅负责创建/销毁 EditorViewController）

EditorViewController (NEW, ~400-600行)
├── 音频数据加载（AVAudioFile → PCMBuffer）
├── 编辑操作（裁剪/静音/标准化/淡入淡出）
├── 撤销/重做栈管理
├── 预览播放
└── 保存/另存为
```

**理由：**
- MainViewController 已 1600 行，再加编辑功能会失控
- 编辑器有独立的生命周期（进入/退出），适合独立 VC
- 编辑器的状态（选区、撤销栈、缩放级别）与录制状态完全独立

**接口设计：**

```swift
protocol EditorViewControllerDelegate: AnyObject {
    func editorDidSave(_ editor: EditorViewController, file: RecordedFileInfo)
    func editorDidCancel(_ editor: EditorViewController)
}

class EditorViewController {
    let file: RecordedFileInfo
    weak var delegate: EditorViewControllerDelegate?
    
    // 编辑器的根视图
    var editorView: NSView { get }
    
    init(file: RecordedFileInfo)
}
```

### AD-03: 编辑器波形——独立 View + 坐标变换系统

**决策：新建 `EditorWaveformView`，不修改现有 `WaveformView`。**

**理由：**
- 现有 `WaveformView` 是 573 行的稳定组件，服务录制+播放两个场景
- 编辑器波形需要缩放/滚动/选区三个全新维度，改造现有 View 风险极高
- 两个 View 共享 `extractWaveformSamples()` 算法，但渲染管线完全不同

**数据模型：**

```swift
struct EditorWaveformState {
    var allSamples: [Float]           // 完整波形数据（文件级）
    var sampleRate: Double            // 采样率
    var totalDuration: TimeInterval   // 总时长
    
    // 视口
    var visibleTimeRange: ClosedRange<TimeInterval>  // 当前可见时间范围
    var zoomLevel: CGFloat            // 1.0 = fitAll，>1.0 = 放大
    
    // 选区（可选）
    var selection: ClosedRange<TimeInterval>?
    
    // 播放游标
    var playbackTime: TimeInterval?
}
```

**坐标变换：**

```
时间 → 像素:  x = (time - visibleRange.start) / visibleRange.duration * viewWidth
像素 → 时间:  time = visibleRange.start + (x / viewWidth) * visibleRange.duration
```

**缩放锚点：** 以鼠标位置为锚点，保持鼠标下的时间点不动。

```swift
func zoom(factor: CGFloat, anchorX: CGFloat) {
    let anchorTime = pixelToTime(anchorX)
    let newDuration = visibleRange.duration / factor
    let newStart = anchorTime - (anchorX / viewWidth) * newDuration
    visibleTimeRange = newStart...(newStart + newDuration)
}
```

### AD-04: 撤销/重做系统——Command 模式 + 差量存储

**决策：Command 模式 + PCMBuffer 差量存储。**

**内存风险分析（枢标记的核心风险）：**

| 方案 | 10min 48kHz stereo × 20步 | 评估 |
|------|--------------------------|------|
| 全量快照 | 20 × 57.6MB = 1.15GB | ❌ 内存爆炸 |
| 差量存储（只存变更区间） | 裁剪: ~0, 标准化: ~57MB, 淡入淡出: ~5MB | ✅ 可控 |
| 磁盘临时文件 | 20 × 57MB 磁盘 | ⚠️ 保底方案 |

**决策：差量 Command 模式为主，磁盘缓存为保底。**

```swift
protocol EditCommand {
    var description: String { get }
    func execute(on buffer: AVAudioPCMBuffer) -> AVAudioPCMBuffer
    func undo(on buffer: AVAudioPCMBuffer) -> AVAudioPCMBuffer
}

class TrimCommand: EditCommand {
    let trimRange: ClosedRange<AVAudioFramePosition>
    private var removedData: AVAudioPCMBuffer?  // undo 时恢复
    
    func execute(on buffer: AVAudioPCMBuffer) -> AVAudioPCMBuffer {
        // 保存被裁掉的数据（差量）
        removedData = extractRange(buffer, range: trimRange)
        // 返回裁剪后的 buffer
        return removeRange(buffer, range: trimRange)
    }
    
    func undo(on buffer: AVAudioPCMBuffer) -> AVAudioPCMBuffer {
        // 在原位置插入保存的数据
        return insertAt(buffer, data: removedData!, at: trimRange.lowerBound)
    }
}

class EditHistory {
    private var commands: [EditCommand] = []
    private var currentIndex: Int = -1
    let maxSteps = 20
    
    func execute(_ command: EditCommand, on buffer: inout AVAudioPCMBuffer) {
        // 清除 currentIndex 之后的 redo 历史
        if currentIndex < commands.count - 1 {
            commands.removeSubrange((currentIndex + 1)...)
        }
        // 执行
        buffer = command.execute(on: buffer)
        commands.append(command)
        currentIndex = commands.count - 1
        // 超过 maxSteps 移除最早的
        if commands.count > maxSteps {
            commands.removeFirst()
            currentIndex -= 1
        }
    }
    
    var canUndo: Bool { currentIndex >= 0 }
    var canRedo: Bool { currentIndex < commands.count - 1 }
}
```

**各操作的差量存储成本：**

| 操作 | execute 存什么 | undo 成本 | 内存影响 |
|------|---------------|----------|---------|
| 裁剪首尾 | 被裁掉的 PCM 段 | 插回原位 | 很小（通常裁几秒） |
| 静音裁剪 | 被删段的 PCM + 位置信息 | 多段插回 | 中等（多个静音段） |
| 音量标准化 | 原始 PCM 全量副本 | 替换回去 | **大** — 需磁盘缓存 |
| 淡入淡出 | 受影响区间的原始 PCM | 替换回去 | 小（通常 1-5 秒） |

**标准化的特殊处理：** 标准化修改整个 buffer 的每一个采样，差量存储无意义。对于标准化命令，使用磁盘临时文件存储 undo 数据：

```swift
class NormalizeCommand: EditCommand {
    private var undoFileURL: URL?  // 磁盘临时文件
    
    func execute(on buffer: AVAudioPCMBuffer) -> AVAudioPCMBuffer {
        // 保存到临时文件
        undoFileURL = saveToDisk(buffer, prefix: "undo-normalize")
        // 执行标准化
        return normalize(buffer)
    }
    
    func undo(on buffer: AVAudioPCMBuffer) -> AVAudioPCMBuffer {
        return loadFromDisk(undoFileURL!)
    }
}
```

### AD-05: 文件锁定——轻量级内存标志

**决策：不用文件系统锁，用内存状态标志。**

```swift
class EditorViewController {
    private(set) var editingFile: RecordedFileInfo?
    
    // MainViewController 在进入编辑器前设置
    static var currentlyEditingURL: URL?
}
```

在 `RecordedFilesView` 中检查：
- 如果 `file.url == EditorViewController.currentlyEditingURL` → 显示 "EDITING" 徽章
- 双击该文件 → 不响应（禁止播放正在编辑的文件）

**理由：** 单进程 App，无需跨进程文件锁。内存标志最简单、最可靠。

### AD-06: 编辑操作基于内存 PCMBuffer

**决策：进入编辑器时将完整文件加载到 `AVAudioPCMBuffer`，所有编辑在内存中进行，保存时才写磁盘。**

```
进入编辑器
  │
  ▼
AVAudioFile(forReading: url) → AVAudioPCMBuffer (全量加载到内存)
  │
  ▼
所有编辑操作在 PCMBuffer 上进行（不碰原文件）
  │
  ├─ 保存 → 写入原文件 URL（覆盖）
  ├─ 另存为 → 写入新 URL
  └─ 放弃 → 释放 PCMBuffer，不写磁盘
```

**内存估算：**

| 音频时长 | 48kHz / 16bit / Stereo | 48kHz / 32bit float / Stereo |
|---------|----------------------|----------------------------|
| 1 min | 11.5 MB | 23 MB |
| 5 min | 57.6 MB | 115 MB |
| 10 min | 115 MB | 230 MB |
| 30 min | 345 MB | 691 MB |

**10 分钟以内完全可以全内存。** 超过 10 分钟需要分段加载（LOD），但 V1.1 可以先限制：

```swift
let maxEditableSize: Int64 = 500 * 1024 * 1024  // 500MB

func canEdit(file: RecordedFileInfo) -> Bool {
    return file.size < maxEditableSize
}
```

超过阈值时提示用户："文件过大（>500MB），请先裁剪后再编辑"。这是合理的 V1.1 限制。

## 三、数据流分析

### 正常路径

```
用户点击「编辑」
  → MainViewController.enterEditor(file:)
  → EditorViewController.init(file:)
  → AVAudioFile → PCMBuffer（后台线程加载）
  → EditorWaveformView.loadSamples(buffer)
  → 用户操作编辑工具
  → EditCommand.execute() → 新 PCMBuffer
  → EditorWaveformView.reload()
  → 用户点击「保存」
  → AVAudioFile(forWriting:) ← PCMBuffer
  → delegate.editorDidSave()
  → MainViewController.showRecording() + 刷新文件列表
```

### Nil/空路径

| 场景 | 处理 |
|------|------|
| 文件不存在（被外部删除） | 进入编辑器时检查，弹 NSAlert "文件已删除" |
| 文件为空（0 字节） | `AVAudioFile` 初始化失败，catch 后显示错误状态 |
| PCMBuffer 分配失败（内存不足） | catch 后提示 "内存不足，请关闭其他应用" |
| 选区为空时点裁剪 | 按钮灰显（disabled），不响应 |

### 错误路径

| 场景 | 处理 |
|------|------|
| 保存时磁盘满 | catch → NSAlert "磁盘空间不足" → 建议另存为到其他位置 |
| 保存时文件被占用 | catch → NSAlert "文件被占用" → 建议另存为 |
| 编辑中 App 崩溃 | **不可恢复**（V1.1 限制）。V1.2 考虑 autosave |
| 音频格式不支持 | `AVAudioFile` 初始化失败 → 提示 "不支持的格式" |

### 并发安全

| 场景 | 风险 | 缓解 |
|------|------|------|
| 编辑中用户在 Sidebar 双击同一文件 | 播放 vs 编辑同时访问文件 | `EditorViewController.currentlyEditingURL` 检查 → 禁止播放 |
| 编辑中用户点录制 | 录制写新文件，不冲突 | 录制中禁止进入编辑器（按钮禁用） |
| 编辑中用户在 Sidebar 选择其他文件 | 需要退出编辑器 | 弹确认对话框（未保存时） |
| 波形加载中用户执行编辑 | PCMBuffer 可能还没加载完 | 加载完成前编辑工具全部禁用 |

## 五、性能评估

### 波形渲染性能

| 场景 | 数据量 | 策略 |
|------|-------|------|
| fitAll（10min 音频） | ~28,800,000 帧 → 降采样到 ~600 个柱 | extractWaveformSamples 现有算法 |
| 最大缩放 | ~4800 帧/视口 → 直接渲染 | 无性能问题 |
| 缩放过渡 | 重新计算降采样 | **潜在卡顿** → 需要 LOD 缓存 |

**LOD 策略：**
预计算 3 级分辨率缓存：
- L0: 1 采样/像素（最大缩放用）
- L1: 100 帧/柱（中等缩放用）
- L2: 全文件/600 柱（fitAll 用）

缩放时根据 `zoomLevel` 选择最近的 LOD 层，避免每次缩放都重新扫描全文件。

### 编辑操作性能

| 操作 | 10min 音频耗时估算 | 线程 |
|------|------------------|------|
| 裁剪 | <10ms（内存 copy） | 主线程 |
| 静音检测 | ~200ms（全文件扫描） | 后台线程 |
| 标准化 | ~50ms（全 buffer 乘法） | 后台线程 |
| 淡入淡出 | <10ms（选区内乘法） | 主线程 |
| 保存到磁盘 | ~500ms（57MB 写入） | 后台线程 |

**规则：** 超过 50ms 的操作必须放后台线程 + 显示进度指示。

## 六、技术债评估

### 新增技术债

| 项目 | 严重度 | 描述 | 清理时机 |
|------|-------|------|---------|
| TD-01 | 低 | MainViewController 仍然过长（虽然编辑逻辑分离，但录制/播放/文件管理仍混在一起） | V1.2 进一步拆分 |

### 减少技术债

| 项目 | 描述 |
|------|------|
| 编辑器控制器分离 | 避免 MainViewController 继续膨胀，这是正向投资 |

| Design Token 规范化 | 编辑器专用 Token 增加设计体系的完整性 |

**净评估：** 技术债**略减少**。编辑器分离是结构性改善，新增债务均可控。

## 七、测试覆盖缺口（概要级，交鉴展开）

| 测试维度 | 覆盖范围 | 关键用例 |
|---------|---------|---------|
| 编辑器入口 | 正常进入/录制中禁止/文件不存在 | 录制中点编辑按钮应无反应 |
| 波形渲染 | fitAll/缩放/滚动/选区 | 缩放到最大级别后滚动不越界 |
| 裁剪 | 首尾裁剪/全选裁剪/最小选区 | 裁剪到 <100ms 选区应被拒绝 |
| 静音裁剪 | 全静音/无静音/多段静音/阈值边界 | 全静音文件不应产生空文件 |
| 标准化 | 正常/已标准化/纯静音 | 纯静音文件标准化不应 div-by-zero |
| 淡入淡出 | 淡入/淡出/两端/选区为空 | 选区 <100ms 时应拒绝 |
| 撤销/重做 | 20 步限制/混合操作/undo-redo-undo | undo 20 步后再 undo 应无反应 |
| 保存 | 覆盖保存/另存为/磁盘满 | 保存前应自动备份原文件 |
| 快捷键 | 编辑器模式/录制模式/切换后 | 编辑器中 Cmd+R 不应触发录制 |
| 内存 | 10min 音频 + 20 步撤销 | 内存峰值不超过 500MB |

## 八、安全评估

**结论：无安全风险。**

编辑器不涉及网络、用户输入验证、权限提升。所有操作在本地文件系统沙箱内。唯一的文件写入是保存操作，覆盖用户自己的录音文件。

不需要升级到盾。
