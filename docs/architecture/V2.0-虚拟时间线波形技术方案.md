## 一、架构总览

### 当前架构（问题）

```
┌─ EditorViewController ────────────────────────────────┐
│  loadAudio()                                           │
│  ├── AVAudioFile.read(into: buffer) ← 全量读入内存     │
│  └── waveformView.loadAudio(from: buffer)             │
│                                                        │
│  EditorWaveformView                                    │
│  ├── allSamples: [Float] ← 全局压缩数组               │
│  ├── drawWaveformBars()                                │
│  │   └── sampleIndex = allSamples.count * time/total  │
│  ├── scrollWheel → 更新 visibleStartTime              │
│  └── zoomIn/Out → 更新 zoomLevel                      │
└────────────────────────────────────────────────────────┘

问题：
1. 1h/48kHz/stereo = 1.3GB PCM 全量加载 → OOM 或卡死
2. allSamples 固定精度 → 放大后模糊，缩小后浪费
3. 绘制通过全局比例映射 → 精度随缩放丢失
4. 波形展示与编辑 buffer 耦合 → 仅查看也消耗大量内存
```

### 目标架构（V2.0）

```
┌─ EditorViewController ────────────────────────────────┐
│  loadAudio()                                           │
│  ├── 构建 AudioAsset（元数据，不读 PCM）               │
│  ├── 短文件(≤60s): 保留全量 buffer 路径               │
│  └── 长文件(>60s): tile 模式                          │
│                                                        │
│  WaveformTileProvider (NEW)                            │
│  ├── LODSelector: pixelsPerSecond → LOD level          │
│  ├── TileGenerator: 后台分段读取 + peak 提取           │
│  ├── MemoryCache: NSCache<TileKey, Tile>              │
│  ├── DiskCache: ~/Library/Caches/AudioRecord/Waveforms │
│  └── RequestCoordinator: 取消/优先级/generation        │
│                                                        │
│  EditorWaveformView                                    │
│  ├── useTileMode: Bool                                 │
│  ├── currentTiles: [WaveformTile]                     │
│  ├── drawWaveformTiles() ← 按时间映射绘制             │
│  ├── drawFallback() ← 低 LOD 淡化 / skeleton          │
│  ├── scrollWheel → requestVisibleTiles()              │
│  └── zoom → LOD 切换 → requestVisibleTiles()          │
└────────────────────────────────────────────────────────┘
```

### 数据流

```
用户操作(滚动/缩放)
  ↓
TimelineViewport 更新
  ↓
LODConfig.selectLOD(pixelsPerSecond)
  ↓
viewport.requiredTileIndices(lodConfig, totalDuration)
  ↓
WaveformTileProvider.requestTiles(viewport)
  ├── 命中内存缓存 → 立即返回
  ├── 命中磁盘缓存 → 提升到内存 → 返回
  └── 未命中 → 后台生成 → delegate 回调 → needsDisplay
  ↓
EditorWaveformView.draw()
  ├── 有 tile → drawWaveformTiles()
  └── 无 tile → drawFallback() / drawSkeleton()
```

## 二、架构决策

### AD-01: Tile 切分维度——按时间 vs 按像素

| 方案 | 优点 | 缺点 | 评估 |
|------|------|------|------|
| A) 按像素切分 | 绘制时 1:1 对应 | 缩放/窗口变化后缓存全部失效 | ❌ |
| B) 按时间切分 | 缓存跨会话复用，不依赖视口宽度 | 绘制时需要时间→像素映射 | ✅ 推荐 |

**决策：按时间切分。**

**理由：**
- 磁盘缓存的核心价值是跨会话复用，按时间切分的 tile 不受窗口大小影响
- 时间→像素映射已有 `timeToPixel()` 基础设施
- 剪映/Logic Pro/Audacity 均采用时间切分

---

### AD-02: LOD 级别数——3 级 vs 5 级

| 方案 | 覆盖场景 | 内存开销 | 切换频率 |
|------|---------|---------|---------|
| A) 3 级 | 概览/常规/精细 | 低 | 低，但跨度大时精度跳变明显 |
| B) 5 级 | 全局/长段/常规/精细/秒级 | 中 | 适中，过渡平滑 |
| C) 连续 LOD | 任意精度 | 高，缓存命中率低 | 无切换 |

**决策：5 级 LOD。**

**理由：**
- 需求明确要求避免"粗到细跳变"（US-04），5 级过渡比 3 级平滑
- 每级 tile 时长递减（300s→120s→60s→30s→10s），高 LOD 数据量可控
- 连续 LOD 缓存命中率极低，不适合磁盘缓存

**LOD 配置表：**

| LOD | samplesPerPeak | tileDuration | 数据密度 | 适用场景 |
|---:|---:|---:|---|---|
| 0 | 240000 (5s×48kHz) | 300s | ~1 peak/5s | 整段 1h 预览 |
| 1 | 48000 (1s×48kHz) | 120s | ~1 peak/s | 几十分钟视图 |
| 2 | 4800 | 60s | ~10 peaks/s | 几分钟视图 |
| 3 | 960 | 30s | ~50 peaks/s | 几十秒视图 |
| 4 | 480 | 10s | ~100 peaks/s | 秒级编辑 |

---

### AD-03: 后台队列并发度——1 vs 2 vs 4

| 并发度 | 优点 | 缺点 |
|---:|------|------|
| 1 | 无 I/O 争抢 | 多 tile 串行等待，首屏慢 |
| 2 | 平衡 I/O 和响应 | — |
| 4 | 首屏快 | SSD 随机读放大，CPU 峰值高 |

**决策：maxConcurrentOperationCount = 2。**

**理由：**
- macOS 上 AVAudioFile 读取是 I/O bound，2 并发已能饱和 SSD 带宽
- 避免与录制/播放引擎争抢 Audio I/O
- 用户快速滚动时取消策略比并发度更重要

---

### AD-04: 内存缓存策略——NSCache vs 手动 LRU

| 方案 | 优点 | 缺点 |
|------|------|------|
| A) NSCache | 系统自动管理内存压力，线程安全 | 无法精确控制淘汰策略 |
| B) 手动 LRU | 精确控制 | 需自行处理线程安全和内存警告 |

**决策：NSCache，countLimit=200，totalCostLimit=100MB。**

**理由：**
- macOS 内存压力通知由系统管理，NSCache 自动响应
- 200 tiles × 平均 500 peaks × 12 bytes/peak ≈ 1.2MB，远低于 100MB 上限
- 简单可靠，不引入额外复杂度

---

### AD-05: 磁盘缓存格式——JSON vs Codable vs 自定义二进制

| 方案 | 编解码速度 | 文件大小 | 实现复杂度 |
|------|-----------|---------|-----------|
| A) JSON | 慢（字符串解析） | 大（文本） | 低 |
| B) Codable/PropertyList | 中 | 中 | 低 |
| C) 自定义二进制 | 快（memcpy 级） | 最小 | 中 |

**决策：自定义二进制格式。**

**理由：**
- Peak 数据是密集 Float 数组，二进制直接 load 比 JSON 解析快 10x+
- LOD-4 单 tile 可达 1000 peaks × 12 bytes = 12KB，JSON 膨胀到 50KB+
- 格式简单固定（version + header + peaks），不需要通用序列化框架
- 版本号字段支持未来格式升级

**二进制格式：**

```
[version: UInt8]           // 1 byte — 格式版本，当前 = 1
[sourceStartTime: Double]  // 8 bytes
[duration: Double]         // 8 bytes
[samplesPerPeak: Int32]    // 4 bytes
[peakCount: Int32]         // 4 bytes
[peaks: (min:Float, max:Float, rms:Float) × peakCount]  // 12 bytes × N
```

---

### AD-06: 短文件兼容策略——统一 tile vs 双模式

| 方案 | 优点 | 缺点 |
|------|------|------|
| A) 所有文件走 tile | 统一代码路径 | 短文件增加不必要的异步复杂度 |
| B) 短文件保留全量，长文件走 tile | 短文件零改动风险 | 两条代码路径 |

**决策：双模式（阈值：duration > 60s 或 fileSize > 50MB）。**

**理由：**
- 短文件（<60s）当前全量加载 + 编辑工作正常，改动 = 引入回归风险
- 编辑命令（TrimCommand 等）依赖全量 buffer，短文件保持不变
- 长文件的波形展示和编辑 buffer 解耦——展示走 tile，编辑仍可选加载全量

---

### AD-07: Fallback 显示策略

| 场景 | 显示方式 |
|------|---------|
| 目标 LOD 已加载 | 正常绘制 |
| 目标 LOD 未加载，低 LOD 有缓存 | 低 LOD 淡化显示（alpha 0.4），标记为 fallback |
| 无任何可用 tile | 灰色 skeleton 条纹动画 |
| tile 生成失败 | 该区域显示错误占位图标 |

**理由：**
- 避免 US-04 描述的"粗到细跳变"——低 LOD 淡化显示让用户知道"这不是最终精度"
- skeleton 动画比空白更友好，不会让用户误以为无声音

---

### AD-08: 缓存失效策略

缓存 key 必须包含以下因子：

```
assetID = hash(filePath + fileSize + modifiedAt + algorithmVersion)
tileKey = assetID + lodLevel + tileIndex
```

**失效触发：**

| 触发条件 | 失效范围 |
|---------|---------|
| 文件大小变化 | 该文件所有 tiles |
| 文件修改时间变化 | 该文件所有 tiles |
| algorithmVersion 变化 | 全局所有 tiles |
| 用户执行编辑操作（裁剪等） | 该文件所有 tiles（短文件走全量刷新） |

## 五、详细数据模型

### 5.1 AudioAsset

```swift
struct AudioAsset {
    let id: String              // 稳定 ID，由文件元数据 + 算法版本生成
    let url: URL                // 文件路径
    let duration: TimeInterval  // 总时长
    let sampleRate: Double      // 采样率
    let channelCount: Int       // 声道数
    let fileSize: Int64         // 文件大小（字节）
    let modifiedAt: Date        // 修改时间

    /// 生成稳定 ID
    static func makeID(url: URL, fileSize: Int64, modifiedAt: Date, algorithmVersion: Int) -> String {
        let raw = "\(url.path)|\(fileSize)|\(modifiedAt.timeIntervalSince1970)|\(algorithmVersion)"
        var hasher = Hasher()
        hasher.combine(raw)
        return String(format: "%016x", abs(hasher.finalize()))
    }
}
```

**设计要点：**
- `id` 不依赖文件名，避免重命名后缓存失效
- `modifiedAt` 参与 ID 生成，文件被编辑后自动失效
- `algorithmVersion` 参与 ID 生成，算法升级后自动失效

### 5.2 LODConfig

```swift
struct LODConfig {
    let level: Int
    let samplesPerPeak: Int         // 每个 peak 覆盖的音频帧数
    let tileDuration: TimeInterval  // 每个 tile 覆盖的时间长度

    static let allLevels: [LODConfig] = [
        LODConfig(level: 0, samplesPerPeak: 48000 * 5, tileDuration: 300),
        LODConfig(level: 1, samplesPerPeak: 48000,     tileDuration: 120),
        LODConfig(level: 2, samplesPerPeak: 4800,      tileDuration: 60),
        LODConfig(level: 3, samplesPerPeak: 960,       tileDuration: 30),
        LODConfig(level: 4, samplesPerPeak: 480,       tileDuration: 10),
    ]

    /// 根据 pixelsPerSecond 选择 LOD
    static func selectLOD(pixelsPerSecond: CGFloat, sampleRate: Double) -> LODConfig {
        switch pixelsPerSecond {
        case ..<1:    return allLevels[0]
        case 1..<5:   return allLevels[1]
        case 5..<30:  return allLevels[2]
        case 30..<150: return allLevels[3]
        default:      return allLevels[4]
        }
    }
}
```

### 5.3 WaveformTileKey / WaveformPeak / WaveformTile

```swift
struct WaveformTileKey: Hashable {
    let assetID: String
    let lodLevel: Int
    let tileIndex: Int
}

struct WaveformPeak {
    let min: Float   // 负向峰值（≤0）
    let max: Float   // 正向峰值（≥0）
    let rms: Float?  // 可选 RMS，用于响度感知
}

struct WaveformTile {
    let key: WaveformTileKey
    let sourceStartTime: TimeInterval  // 该 tile 在音频中的起始时间
    let duration: TimeInterval         // 该 tile 覆盖的时间长度
    let samplesPerPeak: Int            // 每个 peak 的帧数
    let peaks: [WaveformPeak]          // peak 数据数组
}
```

### 5.4 TimelineViewport

```swift
struct TimelineViewport {
    var visibleStartTime: TimeInterval
    var visibleDuration: TimeInterval
    var viewWidth: CGFloat

    var visibleEndTime: TimeInterval { visibleStartTime + visibleDuration }
    var pixelsPerSecond: CGFloat {
        guard visibleDuration > 0 else { return 0 }
        return viewWidth / CGFloat(visibleDuration)
    }

    /// 计算当前视口需要的 tile 索引（含预取）
    func requiredTileIndices(lodConfig: LODConfig, totalDuration: TimeInterval, prefetchRatio: Double = 0.5) -> [Int] {
        let prefetchDuration = visibleDuration * prefetchRatio
        let fetchStart = max(0, visibleStartTime - prefetchDuration)
        let fetchEnd = min(totalDuration, visibleEndTime + prefetchDuration)
        let startIndex = Int(floor(fetchStart / lodConfig.tileDuration))
        let endIndex = Int(floor(fetchEnd / lodConfig.tileDuration))
        return Array(startIndex...endIndex)
    }

    func timeToPixel(_ time: TimeInterval) -> CGFloat {
        guard visibleDuration > 0 else { return 0 }
        return CGFloat((time - visibleStartTime) / visibleDuration) * viewWidth
    }

    func pixelToTime(_ x: CGFloat) -> TimeInterval {
        guard viewWidth > 0 else { return 0 }
        return visibleStartTime + Double(x / viewWidth) * visibleDuration
    }
}
```

## 六、核心引擎设计

### 6.1 WaveformTileProvider 职责

```
WaveformTileProvider
├── requestTiles(viewport, totalDuration) → [WaveformTile]  // 同步返回已有 tiles
├── delegate: didLoadTiles / didFailForKey                   // 异步回调新 tiles
├── getFallbackTile(key) → WaveformTile?                    // 低 LOD 降级
├── cancelAll()                                              // 切换文件时
└── invalidateAll()                                          // 编辑操作后
```

### 6.2 请求流程

```
requestTiles(viewport)
  │
  ├─ 1. LODConfig.selectLOD(viewport.pixelsPerSecond)
  │
  ├─ 2. viewport.requiredTileIndices(lodConfig, totalDuration)
  │     → [tileIndex0, tileIndex1, ..., tileIndexN]
  │
  ├─ 3. currentRequestGeneration += 1  // 使旧请求失效
  │
  ├─ 4. cancelOutdatedOperations(keepKeys: 当前需要的 keys)
  │
  ├─ 5. 对每个 tileIndex:
  │     ├─ 命中 memoryCache → append to available
  │     ├─ 命中 diskCache → 提升到 memoryCache → append to available
  │     └─ 未命中 → append to missing
  │
  ├─ 6. 对每个 missing key:
  │     └─ scheduleTileGeneration(key, lodConfig, generation)
  │
  └─ 7. return available
```

### 6.3 Tile 生成流程

```
scheduleTileGeneration(key, lodConfig, generation)
  │
  ├─ 检查 pendingOperations[key] 是否已存在 → 跳过
  │
  └─ 创建 BlockOperation:
       │
       ├─ 检查 generation == currentRequestGeneration → 否则 return
       │
       ├─ 计算 tileStartTime = tileIndex × tileDuration
       │
       ├─ AVAudioFile(forReading: asset.url)
       │   └─ framePosition = tileStartTime × sampleRate
       │
       ├─ AVAudioPCMBuffer(frameCapacity: tileDuration × sampleRate)
       │   └─ audioFile.read(into: buffer, frameCount: ...)
       │
       ├─ extractPeaks(buffer, samplesPerPeak)
       │   └─ 遍历帧，每 samplesPerPeak 帧提取 min/max/rms
       │
       ├─ 构建 WaveformTile
       │
       ├─ memoryCache.setObject(tile)
       ├─ diskCache.saveTile(tile)
       │
       └─ DispatchQueue.main.async { delegate?.didLoadTiles([key]) }
```

### 6.4 取消策略

| 场景 | 取消方式 |
|------|---------|
| 用户快速滚动 | generation 递增，旧 generation 的 operation 检查后 return |
| 用户缩放导致 LOD 变化 | cancelOutdatedOperations 取消不在新 keepKeys 中的 operations |
| 用户切换文件 | cancelAll() 取消所有 + 清空 pendingOperations |
| 用户关闭编辑器 | cancelAll() |

**关键保证：** 取消后旧任务不会覆盖新视口的显示结果（通过 generation 检查）。

### 7.4 drawWaveformTiles() 核心逻辑

```swift
private func drawWaveformTiles(in rect: NSRect) {
    let centerY = waveformRect.midY
    let drawHeight = waveformRect.height * 0.82

    for tile in currentTiles {
        guard !tile.peaks.isEmpty, tile.duration > 0 else { continue }
        let peakDuration = tile.duration / Double(tile.peaks.count)

        for (i, peak) in tile.peaks.enumerated() {
            let peakTime = tile.sourceStartTime + Double(i) * peakDuration

            // 跳过视口外的 peaks
            guard peakTime + peakDuration >= visibleStartTime,
                  peakTime <= visibleStartTime + visibleDuration else { continue }

            let x = timeToPixel(peakTime)
            guard x >= waveformRect.minX - barWidth,
                  x <= waveformRect.maxX + barWidth else { continue }

            // 使用 min/max 绘制上下振幅
            let topAmplitude = CGFloat(peak.max) * drawHeight * 0.5
            let bottomAmplitude = CGFloat(abs(peak.min)) * drawHeight * 0.5
            let amplitude = max(topAmplitude, bottomAmplitude, 1.5)

            // 选区内外透明度差异
            let isInSelection = selection.map { $0.contains(peakTime) } ?? true
            let level = max(abs(peak.max), abs(peak.min))
            let alpha: CGFloat = isInSelection
                ? max(0.34, min(1.0, 0.34 + CGFloat(level) * 0.66))
                : max(0.15, min(0.4, 0.15 + CGFloat(level) * 0.25))

            let barRect = NSRect(x: x, y: centerY - amplitude, width: barWidth, height: amplitude * 2)
            let path = NSBezierPath(roundedRect: barRect, xRadius: 0.6, yRadius: 0.6)
            IndustrialColors.waveformCoral.withAlphaComponent(alpha).setFill()
            path.fill()
        }
    }

    // 未覆盖区域绘制 skeleton
    drawSkeletonForMissingTiles(in: rect)
}
```

### 7.5 滚动/缩放触发 tile 请求

```swift
override func scrollWheel(with event: NSEvent) {
    if event.modifierFlags.contains(.command) {
        // 缩放
        let location = convert(event.locationInWindow, from: nil)
        if event.scrollingDeltaY > 0 { zoomIn(anchorX: location.x) }
        else if event.scrollingDeltaY < 0 { zoomOut(anchorX: location.x) }
    } else {
        // 横向滚动
        let scrollAmount = visibleDuration * Double(event.scrollingDeltaX / bounds.width) * 0.5
        visibleStartTime = max(0, min(visibleStartTime - scrollAmount, totalDuration - visibleDuration))
        needsDisplay = true
    }

    // tile 模式下触发请求
    if useTileMode { requestVisibleTiles() }
}
```

## 八、EditorViewController 改造

### 8.1 loadAudio() 分支逻辑

```swift
private func loadAudio() {
    EditorViewController.currentlyEditingURL = file.url
    waveformView.setLoadingState()
    navigationBar.setAllToolsEnabled(false)

    DispatchQueue.global(qos: .userInitiated).async { [weak self] in
        guard let self else { return }

        do {
            let audioFile = try AVAudioFile(forReading: self.file.url)
            let format = audioFile.processingFormat
            let fileLength = audioFile.length
            let duration = format.sampleRate > 0
                ? Double(fileLength) / format.sampleRate
                : self.file.duration

            // 获取文件属性用于缓存 key
            let attrs = try FileManager.default.attributesOfItem(atPath: self.file.url.path)
            let fileSize = (attrs[.size] as? Int64) ?? 0
            let modifiedAt = (attrs[.modificationDate] as? Date) ?? Date()

            // 判断是否使用 tile 模式
            let useTileMode = duration > 60 || fileSize > 50 * 1024 * 1024

            if useTileMode {
                // === 长文件：tile 模式 ===
                let assetID = AudioAsset.makeID(
                    url: self.file.url, fileSize: fileSize,
                    modifiedAt: modifiedAt, algorithmVersion: WaveformTileProvider.algorithmVersion
                )
                let asset = AudioAsset(
                    id: assetID, url: self.file.url, duration: duration,
                    sampleRate: format.sampleRate, channelCount: Int(format.channelCount),
                    fileSize: fileSize, modifiedAt: modifiedAt
                )

                // 编辑 buffer 可选加载（在可编辑范围内才加载）
                var editBuffer: AVAudioPCMBuffer? = nil
                if !self.shouldRejectFullBufferEditing(duration: duration, format: format) {
                    let frameCount = AVAudioFrameCount(fileLength)
                    if let buffer = AVAudioPCMBuffer(pcmFormat: format, frameCapacity: frameCount) {
                        try audioFile.read(into: buffer)
                        editBuffer = buffer
                    }
                }

                DispatchQueue.main.async {
                    self.audioBuffer = editBuffer
                    self.audioFormat = format
                    self.waveformView.loadAudioAsset(asset)
                    self.navigationBar.setAllToolsEnabled(editBuffer != nil)
                    if editBuffer != nil {
                        self.navigationBar.setToolEnabled(.trim, enabled: false)
                    }
                    self.updateStatusBar()
                }
            } else {
                // === 短文件：保留原有全量路径 ===
                // ... 现有逻辑不变 ...
            }
        } catch {
            // ... 现有错误处理不变 ...
        }
    }
}
```

### 8.2 编辑操作后刷新

```swift
func executeCommand(_ command: EditCommand) {
    guard var buffer = audioBuffer else { return }

    if editHistory.execute(command, on: &buffer) {
        audioBuffer = buffer
        hasUnsavedChanges = true

        if waveformView.useTileMode {
            // tile 模式：invalidate 缓存后重新请求
            waveformView.invalidateTiles()

        }

        updateStatusBar()
    }
}
```

## 十一、风险评估

| 风险 | 严重度 | 缓解措施 |
|------|--------|---------|
| 编辑后波形刷新：裁剪/静音后 tiles 失效 | 高 | 短文件走全量刷新；长文件 invalidateAll() 后重新生成 |
| tile 生成时的文件锁：后台读取与编辑冲突 | 中 | tile 生成读磁盘原始文件，编辑操作修改内存 buffer，两者解耦 |
| 缩放动画流畅性：LOD 切换时闪烁 | 中 | fallback 策略：低 LOD 淡化显示，避免空白 |
| 内存峰值：大文件同时加载编辑 buffer + tiles | 中 | 超大文件（>30min）不加载编辑 buffer，仅查看 |
| 磁盘缓存膨胀 | 低 | 缓存目录在 ~/Library/Caches，系统可自动清理 |
| AVAudioFile 并发读取安全 | 低 | 每个 operation 独立创建 AVAudioFile 实例 |
