# TC-011 录制区切换状态重置（编辑器 → 录制 Tab）

> 创建：Tab | 2026-09-20 | 驱动方式：UXEvents 回放断言（不再用 computer-use）
> 关联 bug：录制完成 → 自动进编辑器 → 点「录制」Tab 切回后，右侧波形区仍显示上一次录音（脏状态）。

## 一、根因（修复前）

1. `WaveformView.stopRecording()` 有意保留波形数据（等 `loadWaveform` 替换）
2. `MainViewController` 承诺的替换路径 `loadFileWaveform(url:)` 从未被调用（死代码）
3. `MainWindowView.hideEditor()` 只恢复 `recordingContentView` 可见性，从不清理波形
4. 次生：`StatusBarView.updateStatus` 用 `contains("录")` 单字匹配，idle 态「录制目标：…」被显示成「● 录制中」

## 二、修复（2026-09-20）

- `MainWindowView.hideEditor()`：切回录制区时 `waveformView.reset()` + `levelMeterCardView.reset()` + `lastCompletedFile = nil`，并埋 `record_area_reset` 状态事件
- `StatusBarView.updateStatus`：只有「录制中/正在录制/RECORDING」才显示录制中，新增「停止录制/正在停止」→ 停止中

## 三、驱动与断言（可观测性通道）

驱动：AX 坐标点击（文件 Tab → 第一行文件 → 录制 Tab），零截图依赖。
断言：UXEvents JSONL 事件序列（epoch_ms 过滤本次注入）：

```
tab_changed(recordedFiles) → editor_shown → tab_changed(audioRecorder) → record_area_reset
```

`record_area_reset` 缺失 = 切回录制区未重置 = FAIL。

```bash
bash build-app.sh
python3 scripts/tc011_record_area_reset.py
```

## 四、场景边界

| 场景 | 覆盖 | 说明 |
|---|---|---|
| A 文件列表 → 编辑器 → 切回录制 | ✅ 本用例自动化 | hideEditor 唯一修复点，录制完成自动进编辑器也走同一路径 |
| B 真实录制 → 自动进编辑器 → 切回 | 手工/后续扩展 | 与 A 共享 hideEditor()，回归可先跑 A |
| C 编辑器内点侧边栏换音源 | 同源路径 | `sidebarViewDidChangeSourceSelection` → hideEditor()，同样被修复覆盖 |

## 五、已知交互坑

- 文件行是自绘 NSView，无 AX 元素 → 用窗口坐标点击（1200x750 固定布局，见脚本常量）
- 「录制」Tab x≈61 由「文件」Tab 实测 x=171 反推（按钮宽 106 + gap 4）
- AX 语义点击不进 input 层（UXEvents 无 CLICK 行）属预期，action/state 层埋点足够断言
- **截图只截窗口不切屏**：Quartz CGWindowList 后台拿窗口 ID → `screencapture -x -o -l <id>`（-o 去阴影，产出 2400x1500 窗口本体）。System Events 的 `click at` 落点漂移不可用，点击注入用 Quartz CGEvent（落点精确且进 input 层）。点击需要窗口可见（被遮挡会点中遮挡者），截图不需要
