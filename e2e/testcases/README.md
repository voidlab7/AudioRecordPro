# E2E 测试计划 — Tapture（audio_record_mac）

> 维护：Tab | 最后更新：2026-09-18

## 一、设计方法论：双通道证据链

Computer Use 截图只能证明「界面表现」，不能证明「功能事实」。录音 App 尤其如此——UI 说「导出成功」不等于磁盘上有正确编码的文件。

每个用例 = **CU 操作序列（驱动） + 关键帧截图（表现证据） + 落盘硬验证（事实证据）**，三者缺一不可。

### 断言手段（A 系，怎么判定）——与测试层级（L 系，测什么）正交

| 级别 | 手段 | 证明什么 | 示例 |
|---|---|---|---|
| A1 表现 | CU 截图 | 界面状态变化 | 状态徽标「录制中」、电平表活动、波形渲染 |
| A2 结构 | get_app_state（AX 树） | 元素存在/状态/文案，可机判 | 进程列表项、文件列表、按钮可用态 |
| A3 事实 | shell（afinfo / Python wave / ffmpeg） | 功能真实生效 | 文件存在、编码正确、时长、RMS 非静音、频谱成分 |

**铁律：A3 事实断言不过 = 用例 FAIL，截图再好看也是假成功。**

## 一点五、测试分层（测试金字塔）

| 层 | 测什么 | 载体 | 占比 |
|---|---|---|---|
| L1 单元 | 编码参数选择、RMS 计算、状态机、文件命名等纯逻辑 | XCTest（`AudioRecordKit` / App 层纯函数） | 最多 |
| L2 管线/交互 | ① 管线级：喂确定性音源/PCM buffer，验编码转换与时长统计；② UI 交互：视图切换、选中态、按钮态 | XCTest + 确定性音源；UI 切换用 AX 断言（XCUITest 或 computer-use 短脚本） | 中 |
| L3 链路 | 完整用户功能全程（TC-001~007） | computer-use GUI 自动化 + A3 硬验证 | 少而精 |

**录音 App 的中层修正**：核心音频链路（ProcessTap、Aggregate Device、编码）依赖系统权限与真实音频硬件，无法纯单元测——因此 L2 的「管线级测试」是本项目的金字塔重心：用确定性正弦波音源（见下节）驱动，验证编码、格式转换、时长统计等半系统逻辑。A3 断言在 L2（验输出文件）与 L3（验全程产物）都要用。

## 二、测试确定性设计

GUI 自动化录音 App 最大的敌人是「不可控的音源」。回归用例禁止依赖 QQ 音乐等不可控源，统一用确定性正弦波音源：

```bash
# 确定性音源准备（一次生成，多用例复用）
ffmpeg -y -f lavfi -i "sine=frequency=440:duration=90" -ar 48000 -ac 2 ~/Desktop/taptest_tone440.m4a
ffmpeg -y -f lavfi -i "sine=frequency=880:duration=90" -ar 48000 -ac 2 ~/Desktop/taptest_tone880.m4a
# 播放（afplay 即为独立音频进程，可被 ProcessTap 选中）
afplay ~/Desktop/taptest_tone440.m4a &
```

- 时长可控 → 录制区间与有声区间的对应关系可精确断言
- 频率已知 → 多进程混录可以用频谱断言验证（440Hz + 880Hz 同时存在）
- RMS 可预期 → 非静音断言阈值固定

其他确定性约定：

1. **时长断言用区间**：录制时长 = 点录制→点停止全程（含无声段），断言 ±10s（TC-001 坑 4）
2. **已知 bug 的回归点内置**：BUG-1（0 秒文件）修复前，所有录制用例的硬验证都带「时长 > 0 且非静音」断言，持续暴露
3. **AF 树优先、坐标兜底**：定位元素先 `get_app_state`，命中失败再退化到当帧坐标点击

## 四、功能缺口（老板口头需求 vs 当前实现，2026-09-18 摸底）

| 老板需求 | 当前实现 | 处置 |
|---|---|---|
| 暂停录制 | **不存在**。录制链路只有 开始/停止（`ControlPanelView.recordButton` 录制中变停止方块；Kit 层无 pauseRecording API） | 建议立项 REQ「录制暂停/恢复」→ 实现后补 TC-011 |
| 麦克风单录 | 麦克风是「附加输入」（`SidebarView` 底部 toggle，叠加到录制目标），不支持纯麦克风单录 | 同上，或明确产品上不做单录 |
| 混录 | 已支持：「录制全部系统声音」= 系统混音；进程 + 附加麦克风 = 混录 | TC-002 覆盖 |

## 五、执行与产物落盘

- 执行方式：computer-use GUI 自动化（get_app_state 定位）+ 直接 shell 硬验证
- 产物目录：`e2e/artifacts/<TC-ID>-<YYYYMMDD>/`（截图、导出文件副本、断言输出）
- 交互坑必读：TC-001 文档「已知交互坑」节（NSPopUpButton 首点不生效、NSSavePanel 双确认、录制时长区间断言）
- 沙盒意识：App 内部录音在 `~/Library/Containers/com.voidzhang.audio-record-mac/Data/Documents/AudioRecordings/`；日志在同级 `Logs/`
